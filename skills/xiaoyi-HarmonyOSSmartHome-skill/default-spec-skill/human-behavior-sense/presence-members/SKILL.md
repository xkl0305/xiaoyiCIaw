# 家庭成员识别

## 功能说明

通过综合分析门锁、路由器、AI传感器数据，计算每个家庭成员在家的概率，识别当前在家的具体成员。

## 核心算法

### 1. 基础分计算

| 数据源 | 场景 | 基础分 |
|-------|------|-------|
| **门锁** | 室外开门+无室内开门记录 | 90% |
| | 室外开门+门铃响后室内开门 | 90% |
| | 室外开门+有室内开门记录 | 50% |
| | 无记录 | 0% |
| **路由器** | 手机连接路由器 | 90% |
| | 手机未连接路由器 | 10% |
| **传感器** | 成员房间有人 | 80% |
| | 成员房间无人 | 30% |

### 2. 时间衰减因子

#### 门锁时间衰减

| 门锁场景 | 5分钟内 | 15分钟内 | 30分钟内 | 60分钟外 |
|---------|---------|---------|---------|---------|
| 室外开门+无室内开门 | 90% | 70% | 50% | 30% |
| 室外开门+门铃后室内 | 90% | 60% | 40% | 20% |
| 室外开门+有室内开门 | 50% | 40% | 25% | 10% |

#### 传感器时间衰减

| 传感器场景 | 5分钟内 | 10分钟内 | 30分钟外 |
|-----------|---------|---------|---------|
| 房间有人 | 80% | 60% | 30% |
| 房间无人 | 30% | 40% | 50% |

路由器实时数据，**不做时间衰减**。

### 3. 加权计算

```
最终得分 = (门锁分 × 0.4) + (路由器分 × 0.4) + (传感器分 × 0.2)
```

### 4. 置信度判定

| 最终得分 | 置信度 | 输出 |
|---------|-------|------|
| ≥ 85% | high | 确定在家 |
| 60% - 85% | medium | 可能在家 |
| < 60% | low | 不在家/无法确定 |

## 数据采集

### 1. 门锁数据

- 使用 `get_device_histories` 查询门锁最近60分钟记录
- 筛选该成员的室外开门记录
- 判断是否有对应的室内开门记录

### 2. 路由器数据

- 查询当前连接家庭网络的设备
- 匹配家庭成员的手机MAC地址

### 3. 传感器数据

- 使用 `get_device_messages` 查询传感器最近消息
- 需要预先配置成员-房间映射表

### 4. 成员配置（需预先配置）

```javascript
// 成员-房间映射
const memberRoomMapping = {

};

// 成员-设备MAC映射
const memberDeviceMapping = {

};
```

### 5. 未匹配设备处理

当路由器查询到已连接的手机，但该设备MAC地址未在 `memberDeviceMapping` 中匹配到家庭成员时：

1. 记录该未知设备（设备名、MAC地址）
2. **终止当前执行**
3. 返回询问消息给用户：

```
检测到家庭网络中有未识别的设备，请问这个设备是哪个家庭成员的？
- 设备名称：iPhone 15 Pro
```

### 6. 用户回答设备归属后

当用户回答设备归属后（如"iPhone是爸爸的"），按以下流程处理：

#### 6.1 更新配置

1. 查询路由器获取该设备的 MAC 地址
2. 将 MAC 地址添加到 `memberDeviceMapping`：

```javascript
// 用户回答"iPhone 15 Pro是爸爸的"后
memberDeviceMapping["爸爸"] = "新MAC地址";
```

#### 6.2 重新执行检测

配置更新完成后，自动重新执行成员在家检测：
1. 使用更新后的 `memberDeviceMapping` 重新匹配路由器设备
2. 按算法计算每个成员在家概率
3. 返回最终结果

#### 6.3 返回示例

```
已将 iPhone 15 Pro 绑定到爸爸，现在重新检测谁在家...

根据检测，当前在家成员：
- 爸爸（置信度高，判断依据：手机已连接家庭网络）
- 妈妈（置信度中，判断依据：传感器显示次卧有人）

判断依据：
- 路由器显示爸爸的手机已连接家庭网络
- AI传感器显示次卧有人（8分钟内）
```

### 7. 响应用户回答的触发方式

#### 7.1 触发条件

当用户回答设备归属时（包含设备名和成员名的意图），触发本 skill 的绑定处理逻辑。

#### 7.2 输入参数

```json
{
  "action": "bind_device",
  "deviceName": "iPhone 15 Pro",
  "member": "爸爸"
}
```

#### 7.3 处理流程

1. 根据 `deviceName` 查询路由器获取对应 MAC 地址
2. 将 MAC 地址加入 `memberDeviceMapping[member]`
3. 重新执行成员在家检测
4. 返回最终结果

## 数据缺失处理

| 缺失数据源 | 处理方式 |
|-----------|---------|
| 仅缺门锁 | 用 (传感器×0.25 + 路由器×0.75) 归一化 |
| 仅缺传感器 | 用 (门锁×0.5 + 路由器×0.5) 归一化 |
| 仅缺路由器 | 用 (门锁×0.5 + 传感器×0.5) 归一化 |
| 缺两个 | 用单一数据源，置信度降为low |
| 全缺 | "无法判断" |

## 使用流程

1. 获取家庭成员列表
2. 对每个成员分别查询三端数据（门锁、路由器、传感器）
3. 按算法计算每个成员在家概率
4. 筛选概率≥60%的成员作为在家成员
5. 生成回复结果

## 回复格式

### 识别到具体成员时
```
根据检测，当前在家成员：
- 张三（置信度高，判断依据：门锁记录显示5分钟前进门）
- 李四（置信度中，判断依据：手机已连接家庭网络）

判断依据：
- 门锁记录显示张三于14:30通过指纹开门
- 路由器显示李四的手机已连接家庭网络
```

### 检测到访客时
```
根据检测，当前在家：
- 张三（家庭成员，置信度高）
- 访客1人（无法识别具体身份）

判断依据：
- 门锁记录显示张三于14:30进门
- 门锁记录显示有访客于15:00通过临时密码进门
```

### 无法确定时
```
根据现有设备数据，无法准确判断有哪些成员在家。

原因：
- 部分成员手机未在线
- 门锁记录未包含用户身份信息

建议：
- 在门锁上设置用户名称可提高识别准确性
- 确保家庭成员手机连接家庭网络
```

## 注意事项

1. **隐私保护**：仅提供成员姓名或昵称，不暴露详细信息
2. **不确定性**：当识别不确定性较高时，使用"可能"、"推测"等词语
3. **数据时效性**：说明识别结果基于的时间范围
4. **设备要求**：明确说明需要支持的设备才能进行人员识别
5. **成员配置**：需预先配置成员-房间映射和成员-设备MAC映射
