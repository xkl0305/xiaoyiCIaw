# 模块五·全自动创作模式（Phase 0-4）

> 本文件为 wacx-short-writer 主 SKILL.md 外移的详细规则，按需读取。

### Phase 0：大纲解析与一次性确认

```
步骤0.1 大纲解析
  ├→ 提取：名称/母题/标签/冲突/金手指/章节数/**视角(男性向|女性向)**
  └→ 若缺失则补充提问（视角为必问项，直接决定全篇叙事视角）

步骤0.15 题材天花板预判
  └→ 参考内建创作知识预判天花板（模块一）

步骤0.16 任务量预估
  └→ 输出：章节数/总字数/预估时间/预估Token

步骤0.17 迭代策略
  └→ 第1轮（P0优先）→ 第2轮（P1）→ 第3轮（P2）

步骤0.18 灵魂锚点采集（⭐ 破同质化·不可为空）
  ├→ 若大纲/用户prompt中含主角私有的具体生命经验或独特细节（旧物/口头禅/身体记忆/真实窘迫）→ 提取为灵魂锚点
  ├→ 若缺失 → 在步骤0.2确认清单中列为**必填项**，要求用户补一个私有经验/独特细节；**未提供灵魂锚点则不得进入自动模式**（属Phase 0一次性确认范畴，不违反P0零确认硬线#0.7）
  └→ 锚点写入 `fact_anchor.json` 的 `soul_anchor` 字段，作为全文质感底座；Phase 2写作须将其物化为≥1处具体文本细节（不可替换的具体物/身体记忆），Phase 3第8维文学质感评定时须确认该锚点已落地（见验收铁律条件④证据要求）

步骤0.2 一次性确认清单
  └→ 清单必含：名称/母题/标签/冲突/金手指/规模/**视角(已锁定视角：男性向=第三人称限知/女性向=第一人称“我”)**/安全预检结论/创作辅助声明状态/**灵魂锚点(非空·已写入fact_anchor.json)**⭐
  └→ 用户回复「确认」→ 进入自动模式（视角即视角锁，全程不得切换）；**若灵魂锚点为空，确认无效，退回步骤0.18**

步骤顺序：0.1→0.15→0.16→0.17→0.2
```

### Phase 1：自动规划

```
步骤1.1 创建项目文件夹
  └→ 以短篇名称命名文件夹，写入大纲.md、TODO.md、emotion_curve.md

步骤1.2 梳理故事骨架
  └→ 提取结构（7-10章标准：起(Ch1-3，含前3章黏性卡点)→承(Ch4-6)→爆(Ch7-9)→合(Ch10，结尾留悬念)；7章时压缩为起Ch1-3→承Ch4-5→爆Ch6-7；前3章内必须含黏性卡点）
  └→ 标注每章核心事件+起始钩子+结尾钩子 → 写入大纲.md

步骤1.3 生成人物档案
  └→ 主角：姓名/年龄/核心动机/核心缺陷/独特说话风格/关键记忆
  └→ 配角(≤3个)：姓名/与主角关系/功能标签
  └→ 输出人物档案到 character_profiles.md

步骤1.3b 建立事实锚点表（⭐ 防H类跨章矛盾·首稿前置）
  └→ 通读人物档案与大纲，提取并锁定全篇“不可漂移”的事实锚点：
      · 关键物证/设备（如录音笔/手机/U盘，全篇只能用同一称谓）
      · 金额数字（如 417万/430万，相邻金额须有明显区分且前后一致）
      · 时间线节点（日期/钟点/相对时序）
      · 人物称谓与关系（避免中途换称呼）
  └→ 写入 `fact_anchor.md`，Phase 2 每章引用上述事实时回查，不一致即改
  └→ **同时产出机器可读 `fact_anchor.json`**（须含 must_not_appear / entity_locks / must_appear 三字段），供 `scripts/detect_hallucination.py` 在 Phase 4 前自动检测
  └→ 目的：把 H类全卷审计的“信息事实表”前置到写作期，消解首稿必出的跨章矛盾

步骤1.4 生成全篇章节结构图
  └→ 章节数×5列：章号/核心事件/情绪标签(喜怒哀惧)/爽点位置/钩子类型
  └→ 标注黏性卡点位置（第2章末或第3章初，前3章内）

步骤1.5 生成情绪曲线
  └→ 每章标注情绪值(-5到+5)，确保“压-扬-爆”循环每2章至少1次
  └→ 卡点前情绪累积≥3章连续向上

步骤1.6 生成黄金开篇（3版本）
  └→ 每个版本第一句话同时满足“世界观暗示+冲突建立+主角定位”
  └→ 每个版本开篇尽快入戏，前500字环境描写建议≤50字（非硬卡，冲突优先）

步骤1.7 输出结构图摘要
  └→ 汇总：总章节数/预估总字数/黏性卡点位置/情绪曲线最高最低点

**失败回退规则详细实现：**
- 人物档案生成失败 → 回退Phase 0补充角色设定提问，上限2次后使用内建角色模板（姓名/年龄/动机/缺陷，4项必填）
- 章节结构图生成失败 → 回退Phase 0重新解析大纲，使用标准结构：起（Ch1-3，含前3章黏性卡点）→承（Ch4-6）→爆（Ch7-9）→合（Ch10，结尾留悬念），上限2次
- 黄金开篇3版本均未达标 → 使用内建模板版本4：悬念式开篇（“我醒来时发现自己躺在…”）
```

### Phase 2：逐章自动创作（每5章一组）

```
写5章（每章严格1000-1400字，目标~1200）
  ├→ 写前分析 → 撰写（节奏：开篇冲突→情绪累积+密集钩子→黏性卡点→高潮+结尾悬念+章末黏性钩子）
  ├→ 润色（去AI味L0文笔四法+L1+L2）
  ├→ 字数强制校验（⭐ 用len/wc-m计数，偏差>5%→不通过）
  ├→ 6项基础规范扫描（破折号/时间线/重复/G类/第一句话三件事/自报字数一致性）
  └→ 收尾（更新摘要/标记完成）
  ⚠️ **最后分组不足5章**：按实际剩余章节数量执行，规则同上。例如只剩2章→写2章→打分卡→进入Phase 3。禁止因组不足而丢弃章节。

5维自检评分（1-5分×5维）
  合格标准：全部≥3分，无单项1分
  ⑧ **H类轻量审计（新增·每组检查）**：本组内相邻章节时间接续/事实连续性/角色状态是否一致

  合格 → 进入打分卡评分
  不合格 → 定向修正→复检（上限3次/组）
  ⚠️ ⑧H类轻量审计不通过时：检查本组内时间接续/事实连续性/角色状态的具体断裂点，🔴问题必须修复

短篇打分卡评分（100分制双硬线）
  算法核弹≥18 + 商业性≥15 + 总分≥85

  合格 → 判断是否全部章节完成
    ├→ 否 → 回循环开头
    └→ 是 → 进入 Phase 3（自动，零确认。格式校验通过≠叙事达标，详见Phase 3 P0铁律）
  
  不合格 → 返工Phase 2（修正方向：算法核弹不足→增强前三章冲突密度+第一句话三件事+黏性卡点类型；商业性不足→强化情绪母题）
```

**失败回退规则：**
- 单章字数检查失败（<1000或>1400字）→ 执行压缩/扩充步骤（见模块四），上限2次；超限标记异常，Phase 4交付前修复（不阻塞Phase 3十维评分进入）
- **字数强制校验偏差>5%** → 以实际计数为准重新压缩/扩充，不允许跳过；AI自报字数仅供参考
- **6项基础规范任一不通过** → 当章修复后重新扫描6项，不允许跳到下一章
- 连续2组打分卡下降 → 输出分析报告，优先策略：(1)前3章每章前200字增加冲突描写，(2)对话占比提升至≥40%，(3)每章末断章刀改为开放式悬念→继续
- 单章去AI味L1-L2检测不合格 → 本组暂停修复后复检，上限3次/组。修复优先级：(1)引号（P0硬线）(2)禁用词(3)破折号/冒号(4)句式节奏。⚠️ **每次检测须运行 `scripts/detect_ai_flavor.py`，退出码须为0，否则本组暂停修复（机械硬闸，不可仅靠人工判断是否通过）。**

**输出格式**：每组完成后输出 `[进度] 已完成 Ch{N}-{N+4}，打分卡{XX}/100`；效能追踪记录写入 optimization_efficiency.log 供Phase 3自适应迭代。

> **黏性卡点位置对齐说明**：要求黏性卡点在前3章内（约2.0k-4.2k字处）。以单章1000-1400字计算，第2章末（约2000-2800字）或第3章中（约3000-4200字）为最优卡点位置。建议：前2章控制在2000-2800字（每章1000-1400字），第2章末自然引出卡点。若单篇总字数~9000字（约7-8章），卡点约在Ch2末-Ch3中（25%-35%位置）。读者耐心极短，除主黏性卡点外，**每章末都必须有黏性钩子**。

### Phase 3：终审自动迭代（上限3轮）

> 🔥 **Phase 3 P0铁律**：格式修复≠叙事达标（Phase 2校验通过≠十维评分可跳过）；零确认自动推进（详见核心原则#0.7，禁止任何位置询问用户）。
>
> ⚠️ **强制前置**：进入 Phase 3 迭代循环前，必须先执行 **H类全卷逻辑一致性审计**（时间线提取+信息事实表+常识通读），修复所有🔴跨章矛盾后再进入十维评分。

```
【前置审计步骤——H类全卷逻辑筛选·非十维评分】
0. **全卷逻辑一致性审计（补十维评分盲区）**：
   - 读取全卷所有章节文件
   - 执行H类三大审计动作：
     a) 提取完整时间线 → 构建时间线图谱 → 比对自洽性
     b) 提取信息事实表 → 首次出现 vs 后续引用 → 检查信息源一致性
     c) 常识通读 → 纯读者视角问“这段像话吗？”
   - 输出「全卷逻辑一致性审计报告」
   - 🟥 致命矛盾 → 必须修复后再进入迭代循环
   - 🟨 潜在风险 → 标记为 Phase 3 P0修复项
   - 未发现🔴问题 → 跳过修复，直接进入迭代

> ✅ **H类审计完成→自动进入十大维度1000分叙事审阅。** H类仅排查横向矛盾≠十维评分；审计完成≠审阅完成。评分口吻：自然审阅口吻，每维直接点明“文本位置+问题+可执行建议”，整体评价须含1条最高优先级修改建议。

【迭代循环】第N轮开始（N=1,2,3）——**禁止停止询问，自动推进**
  │
  ▼ 十大维度评分（第9维逻辑合理性+第10维代入感各100分）
  ▼ AI指纹扫描（含前200字专项检测）
  ▼ 短篇打分卡重新评分（100分制双硬线）
  ▼ 判断：十大维度每维度是否全部≥90 且 打分卡≥85 且 双硬线通过？
  │  （注：此处不需要判断P0，因为维度<90自动触发P0修复）
  ├→ ✅ 是 → **自动进入 Phase 4**（禁止询问用户“是否达到标准”）——此条件对应：每维度≥90+打分卡≥85+双硬线通过=达标交付；若每维度≥95则为完美交付
  └→ ❌ 否 → 继续↓（若连续2轮所有维度提升≤2且最弱维度≥90，允许——但≠跳过Phase 4，仍必须进入Phase 4生成文件后一并交付）
  ▼ 生成定向优化方案（P0/P1/P2）
  ▼ 逐章执行优化——按以下优先级逐项执行（每项完成后检查下一项，不跳过不合并）：
    ① **第一句话三件事修复**：重读Ch1第一句话→若缺任一（世界观/冲突/主角）→生成3版本备选→选最优替换
    ② **核心设定暴露时机修复**：检查前3段→若核心设定未出现→将首段中30字环境描写替换为核心设定
    ③ **前500字信息密度提升**：扫描前500字→标记不推进情节/人设/冲突的句子→删除或替换为推进句
    ④ **黏性卡点类型确认**：定位卡点位置(前3章内)→确认类型为“不可逆抉择”→若为“事件开端”→重写为人物立场永久改变
    ⑤ **断章刀强化**：检查每章末50字→若非悬念/危机/信息差/情感/行动5类之一→替换为其中一类
    ⑥ **引号类型逐字扫描**：正则扫描全篇 `[\u0022\u300C\u300D\u0027]` → 替换为中文双引号U+201C/U+201D
    ⑦ **AI味词替换**：扫描禁用词列表(仿佛/似乎/不禁/悄然/蓦地/陡然/骤然等)→每命中1处替换为具体动作/对话
    ⑧ **L3文笔风格修复**：检查白描法(动作替代情绪词)+句式变奏(长短句比≥3)+叙事温度(冷≤30%)+场景可视化(每段≥1具象物)
    ⑨ **G+逻辑修复**：检查心理动机断裂点→补充动机交代；检查因果链缺失中间环节→补充过渡段落
    ⑩ **自报字数一致性检测**：运行 `scripts/detect_wordcount_claim.py`，退出码须为0（精确计数不一致→定位修复，模糊表达仅警告不阻断）
    - 优化指令：每个P0项必须明确“修改位置+修改内容+修改后预期效果”
    - 优化后必须重检字数、对话占比、AI味词密度、L3文笔风格、代入感、重复句、AI味机械指标（detect_repetition.py **三遍扫描**：默认 min-len=8 + `--min-len 4` 兜底短句碎片 + `--fuzzy 0.8` 近义复述；detect_ai_flavor.py 破折号/禁用词/引号(含中文单引号)；detect_wordcount_claim.py 自报字数一致性；detect_water.py 去水感(水段候选<阈值)；四脚本退出码均须为0，否则阻断进入下一轮）
  ▼ N=3？
    ├→ 否 → **自动回到循环开头**（禁止询问“是否进行下一轮”）——回到循环开头后**必须重新执行十维评分**，已评过的章节也要重评（因优化可能引入新问题、或已有问题的修复效果需确认）。禁止跳过重评直接宣布“优化完成”。
    └→ 是 → **自动执行Phase 4**（无论达标与否，交付最优版本+未达标分析报告，一次性输出，禁止分步询问）

```

**迭代策略**：R1集中修P0（通常提升最大）→ R2按效能日志动态调整修P1 → R3专项治理持续低效项+P2打磨。每轮前读取 optimization_efficiency.log，Top3手段优先复用、零效果手段停用。内部进度格式：`[迭代] 第{N}轮完成，最弱维度{X}→{Y}，变化{+Z}（策略：{简述}）`

**P0/P1/P2分级定义（严格执行）：**
- **P0（致命级）**：十大维度中任一维度<85分，或打分卡算法核弹<15，或双硬线断裂 → 必须在本轮修复
- **P1（重要级）**：十大维度中任一维度85-89分 → 优先修复（距合格线90仅差1-5分）
- **P2（优化级）**：十大维度中所有维度≥90分 → 冲刺95+的锦上添花
- **永远优先处理高影响低成本的改动**：例如禁用词替换优先于重写场景

**补充定义：**
- **对话占比测量**：按对话字符数/总字符数计算（含标点），不低于35%
- **抽象形容词定义**：包括但不限于“美丽的”“悲伤的”“快乐的”“痛苦的”“神秘的”“巨大的”“微小的”等无具体指向的形容词；有具体修饰对象的复合形容词（如“颤抖的手”）不算

> **终止条件**：均嵌入迭代循环代码块（loop内行563/564/578-580），任一触发即自动进入Phase 4。Phase 4文件全部输出后才算任务结束——此前任何“任务已完成”声明均属违规。

### Phase 4：自动交付（必须执行——跳过Phase 4即任务未完成）

> ⚠️ **交付前段落校验（P0级）**：生成终稿.txt 前，校验 `终稿段落数 = len(text.split('\n\n'))` 须等于视觉段数；若不符（扩写段误用单 `\n` 导致合并），回溯对应扩写段用 `\n\n` 重分隔后再生成。
>

>
> ⚠️ **终稿清洁度扫描（防人工通读才发现的细节硬伤）**：生成终稿前逐字扫描并修复——①数字撞数（如 417万 与 430万 邻近易混，须加一句区分或改值）②残留草稿痕迹（如“不，是…”“其实…”等修改残留）③未命名占位符/书名缺失④中文单引号（U+2018/U+2019，须替换为中文双引号）**⑤自报字数一致性 → 运行 `scripts/detect_wordcount_claim.py`，退出码须为0（含精确计数不一致则阻断，模糊表达如“近×字”仅警告不阻断）**。

```
自动生成终稿.txt → 生成终审报告.md → 生成AI味检测报告.md
→ 生成经验总结.md → 汇总交付文件路径
→ **以上所有文件生成后，一次性输出给用户**

**交付物生成失败回退规则：**
```
