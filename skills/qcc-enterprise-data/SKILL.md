# qcc-enterprise-data 企查查企业数据综合查询 Skill

本 Skill 统一接入企查查八个 MCP Server，覆盖企业主体与股权核验、企业风险、知识产权与数字资产、经营动态与资质监管、法定代表人与董监高当前及历史画像、非结构化文档解析、法规法条检索与溯源、普通及权威司法案例研究等能力。根据用户问题识别查询主体和任务类型，自动选择或组合对应 Server；涉及企业的跨模块任务先锁定唯一企业主体，再开展风险、经营、知产或人员关联分析。

## 调用规范

1. 所有企查查 MCP Server 请求均使用 `POST`。
2. 所有请求头均包含 `Content-Type: application/json`、`Accept: application/json, text/event-stream` 和 `Authorization: Bearer`。
3. 先根据用户意图选择能力模块，再调用对应的 MCP Server。
4. 每个 MCP Server 先完成 `initialize` 和 `notifications/initialized`，再通过 `tools/list` 获取当前实际开放的工具清单，根据工具描述和 Input Schema 调用 `tools/call`。
5. 不得在本文件中硬编码或推测工具名称、工具数量和工具参数。
6. 查询结果为空时，优先提示用户收窄或细化查询条件。
7. **凭证授权失败处理（强制）**：若遇到登录状态异常，优先检查凭证是否缺失或过期，调用一次 `huawei_id_tool`（工具参数：`clientId=118336739`、`skillName=qcc-enterprise-data`），仅调用一次，不可重复调用。刷新成功后重新读取凭证，并且只重试原请求一次；再次失败时提示用户重新授权。

### MCP 生命周期

1. 调用 `initialize`，记录服务端协商的协议版本；服务端返回 `Mcp-Session-Id` 时，同时记录该会话 ID。
2. 发送 `notifications/initialized`。
3. 调用 `tools/list` 获取当前 Server 实际开放的工具。
4. 根据用户意图、工具描述和 Input Schema 调用 `tools/call`。
5. 同一 Server 的后续请求复用其会话信息；不同 Server 不得复用 `Mcp-Session-Id`。

JSON-RPC 请求 ID 在当前调用链中保持唯一。若服务端要求 `MCP-Protocol-Version` 或返回了 `Mcp-Session-Id`，后续请求按协商结果携带对应 Header。

## 能力路由

- **Company Server（主体与股权基座）**：用户要识别或验证企业、查工商登记/简介/联系方式、股东、实际控制人、受益所有人、主要人员、分支机构、对外投资、变更、年报、财务、上市或税号开票信息时使用。简称、品牌名、曾用名或模糊名称先在此解析候选主体；股权穿透、关联风险、高管背调等跨模块任务也先在此取得唯一企业标识与基础股权事实。
- **Risk Server（企业当前风险）**：用户要做风险体检、红线筛查、授信/供应商/交易对手准入或关联方风险排查时使用。覆盖失信、被执行、限高、终本、立案、裁判文书及详情、开庭、法院/送达/劳动仲裁公告、诉前调解、司法拍卖、破产重整与清算、经营异常、严重违法、行政/环保处罚、税务异常/欠税/违法、股权冻结与出质、股票质押、动产/土地抵押、担保、违约、限制出境、注销、惩戒、公示催告、资产询价及财产悬赏等当前风险。
- **IPR Server（知识产权与数字资产）**：用户要盘点技术、品牌、版权、无形资产或线上经营矩阵时使用。覆盖国内外专利、商标与商标文书、软件/作品著作权、集成电路布图、标准、知识产权出质、商业特许经营，以及 APP、网站、小程序、公众号、抖音、快手、微博和线上店铺；适合科技认证、品牌评估、知产融资、侵权线索、竞品与渠道研究。
- **Operation Server（经营动态与资质监管）**：用户要评估经营实力、业务活跃度、供应能力、行业资质或监管合规时使用。覆盖招投标、招聘、融资与融资租赁、投资机构、资质/荣誉、行政/电信许可、纳税人资质、进出口信用、信用评价/承诺、企业/政府/相关公告、新闻舆情、榜单、土地受让/转让、产权交易、资产拍卖、私募基金、科技成果，以及抽查、产品召回、食品安全、广告审查、软件违规、游戏审批、未准入境和假冒化妆品等专项监管信息。财务数据属于 Company Server，不路由到 Operation Server。
- **Executive Server（人员与关联企业画像）**：问题以某位法定代表人、股东或董监高个人为中心，涉及任职、担任法代、控制企业、关联企业、投资、最终受益人身份或个人关联风险时使用；通常需要“唯一企业主体 + 人员姓名”共同锚定同名人员。可查当前及历史任职/投资/关联关系，以及失信、被执行、限高、终本、立案、裁判、开庭/法院/送达公告、诉前调解、行政/税务处罚、股权冻结/出质/质押、限制出境、资产询价和财产悬赏等人员风险。仅查询目标企业的主要人员名单时使用 Company Server。
- **Document Server（非结构化文档入口）**：用户提供可访问的在线文档链接，要求解析 PDF、图片、扫描件、Office、WPS/ET 或复杂表格时使用；先提交解析，将内容转换为 Markdown，长文档或异步任务再查询进度与结果。该远端 Server 不直接读取用户设备上的本地路径；若只有本地文件，应由宿主提供本地解析入口或先转换为可访问链接。取得文本后，可继续做摘要、问答、字段抽取、合同/财报分析；若还需核验企业事实、法规或案例，再把抽取出的主体、法条或案号路由到相应 Server。
- **Regulation Server（法规与法条）**：目标法规明确时按法规名称、发文机关、效力级别、时效状态等精确检索；只有法律问题或案情描述时使用语义检索召回相关法条；需要通读时查询法规结构与全文，需要精确援引时查询逐字法条；对 AI 或文书中的法条引用做真实性、效力和来源核验时使用法规溯源。
- **Case Server（普通与权威案例）**：按案由、法院、审级、裁判日期、当事人等条件找类案时检索普通案例；法律意见、类案报告或需要高权威援引时优先检索指导性、公报、典型等权威案例；需要事实、裁判理由与结果时查询案例详情；需要验证文本中案号真实性和权威出处时使用案例溯源。查询“某企业自身涉及的裁判文书或诉讼风险”优先使用 Risk Server，研究同类裁判规则与案例全文使用 Case Server。

涉及企业数据的跨模块任务，先用 Company Server 锁定唯一企业主体，再按问题组合其他 Server：企业事实走 Company，企业风险走 Risk，以自然人为中心走 Executive，经营与知产分别走 Operation 和 IPR。非结构化材料先走 Document，法律依据与类案研究分别走 Regulation 和 Case，无须预先调用 Company Server。不得仅因关键词重合跨错模块，例如“企业裁判文书”走 Risk 而“类案检索”走 Case。简称或品牌名可能对应多个主体，未锁定唯一主体前不得直接形成企业结论。示例公司名称使用完整注册名称，如“华为技术有限公司”。

## 结果约束

- 只使用 MCP 工具真实返回的数据，不补写、推测或编造企业事实。
- 明确区分“查询无记录”“无权限”“凭证失效”“服务调用失败”，不得把调用失败描述为企业无风险或无记录。
- 工具返回分页信息时，按用户需求继续翻页；未取全量时说明结果范围。
- 工具不存在、未开放或参数校验失败时，重新读取 `tools/list` 和 Input Schema，不猜测工具名称或参数。
- 遇到限流或服务暂时不可用时，说明当前未完成核验，不使用未经 MCP 验证的信息替代结果。

## SKILL 脚本文件中获取 loginToken 的方式

```python
import os


def get_xiaoyi_token() -> str:
    token_file = "/home/sandbox/.openclaw/.xiaoyienv"
    login_token_key = "118336739_login_token"
    login_token = ""

    if os.path.exists(token_file):
        with open(token_file, "r", encoding="utf-8") as token_env:
            for line in token_env:
                line = line.strip()
                if line.startswith(f"{login_token_key}="):
                    login_token = line.split("=", 1)[1].strip()
                    break

    if not login_token:
        raise ValueError(
            "错误：118336739_login_token 为空或未设置，请调用一次 "
            "huawei_id_tool（clientId=118336739，"
            "skillName=qcc-enterprise-data）刷新凭证",
        )

    return login_token
```

注：复用本 Skill 格式时，`qcc-enterprise-data` 应替换为业务自己的 Skill 名称，
`118336739` 应替换为业务在 AGC 申请并在小艺开放平台配置的 `clientId`。
