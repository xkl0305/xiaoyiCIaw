# wacx-docx Skill（Markdown 转 DOCX）

## 功能

将 Markdown（.md）文件自动转换为符合用户 DOCX 基准的格式规范文档。

适用于网文作者将 markdown 草稿（含 `# 标题`、`**加粗**`、列表、引用、代码块、删除线等）一键导出为可投递/可审稿的 Word 文档。

## 格式规范（与用户 DOCX 基准一致）

| 属性 | 值 |
|------|---|
| 字体 | 宋体 小四(12pt)，代码块 Courier New 11pt |
| 对齐 | 左对齐（标题亦左对齐） |
| 行距 | 1.5 倍（乘数模式） |
| 段前后 | 0 |
| 首行缩进 | 304800 EMU（约 2 字符）；**空行/代码块/引用/分页段不缩进** |
| 标题 | 小说名（H1）、卷（H2）、章名（H3）：加粗；H1=16pt / H2=14pt / H3=13pt |
| 分页符 | 每章（章名匹配规则后）前插空段 + `br type=page`；首章前无分页 |
| 引号 | ASCII `"` `'` → 中文全角 `""` `''`（toggle 状态机） |
| 标点 | ASCII `, . ; : ? ! ( )` → 中文全角 `，。；：？！（）`（仅在 CJK 上下文） |
| 破折号 | `--` 或单 `-`（CJK 上下文） → 中文 `——` |
| 省略号 | `...`（3+ 个点） → 中文 `……` |
| 编码 | 自动识别 UTF-8 BOM / UTF-8 / GBK / GB2312 / latin-1 |

## 标点规范化硬规则（GB/T 15834 合规）

1. **代码块 / 行内代码 / URL / 邮箱** 不做任何规范化（保留 ASCII 原样）
2. **正文 / 标题** 默认规范化，--no-punct-norm 可关闭
3. **英文段落保护**：仅当 ASCII 标点前后 1 字符内有 CJK 时才替换，避免破坏纯英文段落
4. **URL/邮箱保护**：先用 `\x00` 包裹占位，规范化后还原
5. **引号 toggle**：先出现为左、后出现为右；嵌套场景由 mistune AST 决定归属
6. **破折号/省略号优先处理**：在字符级映射之前完成，避免破折号中间的 `-` 被误替换
7. **跨 token 上下文**：标点字符位于单字符 text token 内时（如 `粗体,斜体` 中的 `,`），借助兄弟 token 的首尾字符判断 CJK 上下文

## 分段硬规则

1. **MD 空行分段**：连续空行 = 段落分隔符
2. **MD 单换行合并**：默认合并为同一段落内的连续文本（与 Word 段落语义一致）
3. **强制换行保留**：行尾两空格 或 `\` 结尾 → 段落内插入 `<w:br/>`（DOCX 软换行）
4. **空段落压缩**：空 paragraph 节点（无任何文本）不生成 DOCX 段
5. **章节标题前分页**：H1/H2/H3 文本匹配 `第X章/第X卷/X之幕/X季` 规则时，从第 2 章起插分页
6. **代码块独立行**：代码块每行渲染为独立 DOCX 段，等宽字体，无首行缩进

## MD 语法 → DOCX 映射

| MD 语法 | DOCX 处理 |
|---------|-----------|
| `# H1` 小说名 | 加粗段（自动检测为书名时插入，否则正常标题） |
| `## H2` 卷名 | 加粗段，H2=14pt |
| `### H3` 章名 | 加粗段，H3=13pt（章名前加分页） |
| `#### H4+` 副标题 | 加粗段，12pt（无分页） |
| 普通段落 | 正文段，首行缩进 2 字符 |
| `**bold**` | run.bold = True |
| `*italic*` | run.italic = True |
| `~~strike~~` | run.font.strike = True |
| `` `code` `` | Courier New 等宽 run |
| `- item` 列表 | `· item` 段（首行缩进），支持嵌套列表（逐层缩进） |
| `- [ ]` 任务列表 | `☐ item` / `☑ item` 段（勾选状态） |
| `1. item` 列表 | `1. item` 段（首行缩进） |
| ` ```code``` ` | 多段等宽文字（无缩进） |
| `> quote` | 缩进引用段（left_indent=1 字符） |
| `\| 列A \| 列B \|` 表格 | 带边框 DOCX 表格（Table Grid，表头加粗，自动适配行数） |
| `---` 分隔线 | 空段 |
| `![alt](url)` | 占位 `【图片：alt】` |
| `[text](url)` | 仅显示 `text`（DOCX 不保留超链接） |

## 工作流程

```
接收 MD 路径
  │
  ▼
步骤 1：文件校验
  ├─ 文件是否存在？ 否 → 提示用户确认路径
  ├─ 文件是否为空？ 是 → 提示"文件内容为空"
  └─ 文件大小>50万字？ 是 → 提醒分批处理
  │
  ▼
步骤 2：编码检测（自动多级 fallback）
  └─ UTF-8 BOM → UTF-8 → GBK → GB2312 → latin-1
  │
  ▼
步骤 3：MD 解析（mistune 3.x，AST 模式）
  ├─ 扫描整篇 → token 流（heading/paragraph/list/code/quote/...）
  └─ 检测首 H1 是否为书名（不匹配章名规则时）→ 候选书名
  │
  ▼
【检查点 ★】书名确认（防止错判）
  ├─ 用户在 prompt 中明确指定书名 → 用用户指定（--title 参数）
  ├─ MD 首 H1 文本明显是书名（如"人间节气录"）→ 直接采用
  ├─ MD 首 H1 文本像章名（如"第一章 起始"）但没匹配规则 → 用 ask_user 确认
  │   "我检测到候选书名是 X，是否正确？1=是 / 2=用其他书名 / 3=不加书名"
  └─ MD 没有首 H1 → 不加书名，文档开头直接进入正文
  │
  ▼
步骤 4：标点规范化（按节点类型）
  ├─ heading / paragraph / list / quote → 走 normalize_punctuation
  └─ code block / codespan / link url → 跳过
  │
  ▼
步骤 5：DOCX 生成
  ├─ 设置 Normal 默认样式（宋体小四/1.5倍行距/首行缩进）
  ├─ 逐 token 渲染：
  │   ├─ heading → 加粗段 + 章名匹配则加分页 + 字号映射
  │   ├─ paragraph → 首行缩进段
  │   ├─ list → 列表段（递归渲染嵌套列表；任务列表转 ☐/☑）
  │   ├─ table → 带边框 DOCX 表格（表头加粗）
  │   ├─ block_code → 多段等宽
  │   ├─ block_quote → 缩进引用段
  │   └─ thematic_break → 空段
  └─ 末尾保存
  │
  ▼
步骤 6：交付
  ├─ 输出文件路径、编码检测结果、token 数、段落数、标题数、分页符数
  └─ 【检查点 ★】交付前若生成文件大小 > 50MB 或段落数 > 5000，提醒用户
  │
  ▼
交付 DOCX 文件
```

### 检查点使用规范（关键 AI 行为指令）

| 检查点 | 何时触发 | AI 应执行的动作 |
|--------|---------|----------------|
| **★ 书名确认** | 候选书名存在但不确定 | 用 `ask_user` 询问用户确认；用户回复 1=采用/2=修正/3=不加 |
| **★ 交付确认** | 文件超大或段落超长 | 输出风险提示 + 询问"继续导出 / 分批处理 / 取消" |
| **★ 错误恢复** | mistune 抛异常或编码全失败 | 输出错误码（exit 1/2/3）+ 询问下一步 |

## 脚本路径与参数

**主脚本**：`scripts/md_to_docx.py`（基于 mistune 3.x + python-docx 1.x）

**依赖**：
```bash
pip install python-docx mistune
```

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `input` | 输入的 MD 文件路径（必填） | — |
| `-o, --output` | 输出的 DOCX 文件路径 | 同名.docx |
| `--title` | 手动指定书名（跳过自动检测） | 首 H1 自动检测 |
| `--no-punct-norm` | 关闭标点规范化（保留 ASCII 标点） | 开启 |

## 退出码

| 退出码 | 含义 | 处理 |
|--------|------|------|
| 0 | 成功 | — |
| 1 | 文件不存在或参数错误 | 检查路径 |
| 2 | 编码无法识别 | 文本编辑器另存为 UTF-8/GBK |
| 3 | 权限/磁盘错误 | 检查文件占用和目录权限 |
| 4 | 缺少依赖（mistune / python-docx） | 执行 `pip install python-docx mistune` |
| 5 | 文件内容为空 | 为输入文件补充内容 |
| 6 | Markdown 解析失败 | 检查 MD 语法 |

## 示例命令

```bash
# 基本用法（自动检测书名+标点规范化）
python md_to_docx.py 小说.md

# 指定输出文件名
python md_to_docx.py 小说.md -o 导出版.docx

# 手动指定书名（跳过检测）
python md_to_docx.py 小说.md --title "人间节气录"

# 关闭标点规范化（保留 ASCII 标点原样）
python md_to_docx.py 英文段落.md --no-punct-norm
```

## 适用范围

- 本 skill 仅处理 Markdown（`.md`）输入，输出统一使用 `scripts/md_to_docx.py`
- 若输入是纯 TXT 且无需 MD 语法解析与标点规范化，请改用 `ima-doc` skill（本 skill 不适用）
