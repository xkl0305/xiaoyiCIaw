## 触发条件

**必须触发本 Skill 的场景（只要用户通过穗好办查询以下任一政务信息）：**

- **社保类**："查社保"、"社保缴费明细"、"社保记录"、"养老保险"、"缴费记录"、"五险一金"、"我的社保交了多少钱"、"社保交了多久" 等涉及个人社保缴费信息的查询
- **医保机构类**："查医保机构"、"医保机构查询"、"医保定点医院"、"定点医院"、"定点药店"、"医保经办机构"、"医疗机构查询" 等涉及医保定点机构（医院/药店/经办机构/门诊）信息的查询
- **综合类**：用户同时提到多种查询（如"帮我查一下社保和医保机构"），或说 "穗好办查一下我的保障信息" 等模糊表述

**不需要触发本 Skill 的场景：**

- 用户只是询问政策法规、缴费比例、计算方式等知识性问题（不涉及个人数据查询）
- 用户提到其他非医保机构类和社保类的政务查询（户籍、个税等），且未要求通过穗好办查询
- 穗好办技能已排查过该场景，确认该服务不在穗好办 App 内

## 核心设计理念

穗好办 App 提供多种个人政务信息查询服务，但不同服务的操作流程不同：

- **社保查询**：进入后可通过时间选择器和页签切换浏览完整明细，流程固定可自动化
- **医保机构查询**：内部包含多个子服务（定点医院、定点药店、医保经办机构、医疗机构或门诊），均通过搜索框模糊查询即可，不涉及人脸校验

本 Skill 的核心策略是：**统一框架 + 按意图分流 + 细分确认**。先统一完成 App 启动和登录（通用前置），再根据用户意图路由到不同的服务流程。对于医保机构等包含多个子服务的类型，先向用户确认具体业务，再执行对应的操作流程。

## 工作流程

### 第零步：意图识别与分流决策

在开始任何 GUI 操作前，先分析用户输入，判断查询意图：

```
用户输入 → 意图分类 → 确定查询服务类型 → 提取查询参数 → 路由到对应流程
```

**意图分类规则：**

| 关键词/语境                        | 分类结果   | 分流目标             |
| ----------------------------- | ------ | ---------------- |
| 社保、社保缴费、缴费明细、养老保险、养老、工伤、失业、五险 | 社保查询   | 流程 A             |
| 医保机构、定点医院、定点药店、医保经办机构、医疗机构、门诊 | 医保机构查询 | 流程 B（需先确认具体子服务）  |
| 同时提到多种服务                      | 综合查询   | 按优先级依次执行：社保→医保机构 |

##### 医保机构子服务澄清

当用户意图归类为「医保机构查询」时，用户可能只笼统地说"查医保机构"而不清楚具体子服务。**必须先向用户确认具体要查什么**，不能直接开始 GUI 操作：

```
用户说"帮我查一下附近的医保机构" → 询问用户要查的具体业务：
1️⃣ 定点医院查询 — 查询医保定点医疗机构（需提供医院名称）
2️⃣ 定点药店查询 — 查询医保定点零售药店（需提供药店名称）
3️⃣ 医保经办机构查询 — 查询医保经办机构（需提供机构名称）
4️⃣ 医疗机构（门诊）查询 — 查询医疗机构或门诊（需提供机构或门诊名称）
```

所有子服务均通过搜索框模糊查询完成，不涉及人脸校验。如需查询个人参保信息（需人脸识别），请直接打开穗好办 App 操作，本 Skill 暂未覆盖该场景。

**如果用户能直接在初始输入中说清楚具体子服务**（如"帮我查一下最近的三甲定点医院"、"查一下大参林是不是定点药店"），则不需要额外询问，直接路由到对应子服务。

**提取通用查询参数（适用所有流程）：**

- **时间范围**：如果用户指定了时间范围，提取具体起始和结束时间；未指定则默认最近半年。社保查询会用到时间范围，医保机构查询不需要时间范围

### 第一步：启动 App 与登录（共享前置）

调用 `xiaoyi_gui_agent` 工具，按以下顺序执行：

#### 阶段一：检查并启动穗好办 App

1. **全局搜索"穗好办"**：打开应用市场，搜索"穗好办"，检查搜索框下方的第一个搜索匹配卡片右侧是否有"打开"按钮
2. **判断安装状态**：
   - **有"打开"按钮**：点击"打开"按钮打开穗好办 App，进入阶段二
   - **有"安装"按钮**：点击"安装"按钮进入应用安装页面，点击最下方的"安装"按钮，安装完成后点击"打开"按钮打开穗好办app，首次进入app点击协议弹窗的"同意"按钮以及位置请求弹窗的"仅使用期间允许"按钮、发送通知弹窗的"允许"按钮，进入首页后结束搜索app的任务，进入阶段二

#### 阶段二：登录处理

3. **检查登录状态**：判断当前用户是否已登录
   - **未登录**：执行登录流程 → 点击页面底部的**华为图标按钮**（HUAWEI ID 图标，不是"广东政务服务"按钮）→ 跳转到华为账号授权页 → 授权手机号快速登录 → 等待登录成功进入首页
   - **已登录**：直接进入首页，跳过登录步骤

### 第二步：按意图分流执行

根据第零步的分类结果，选择对应的流程：

#### 流程 A：社保查询（全自动化）

适用于查询"社保缴费明细"。这是最成熟的流程，全程可 GUI 自动化完成。

##### A1. 导航到社保查询页面

回到穗好办首页 → 点击首页搜索框 → 输入"社保缴费明细查询" → 在搜索结果中点击最匹配的服务卡片 → 进入社保查询详情页面

##### A2. 查询社保缴费明细

1. **设置查询时间**：
   - 如果用户指定了时间范围，在时间选择器中设置对应的起始和结束月份。轻微滑动时间滚条中用户指定的年份和月份到中间高亮区域（不要直接滑到底部，确保精准选中目标值），同时点击"确认"按钮开始查询。若整体滑动操作过程大于1min应引导用户接管任务手动选择时间范围
   - 如果用户未指定时间范围，不做任何操作（系统默认返回最近半年的数据）
2. **浏览并记录数据**：点击确认查询后，直接开始操作：
   - 依次切换"养老"、"工伤"、"失业"三个页签
   - 逐页浏览并记录每一页显示的每一条数据
   - 将数据汇总整理好一并返回
3. 至此，当前时间段查询结束

##### A3. 继续查询其他时间段（可选）

当用户查询完一个时间段还需要查另一个时：

- **不要重新搜索服务入口**，直接在当前已打开的社保查询页面上操作：
  - 找到时间选择器，修改起始和结束月份
  - 点击"确认"重新查询
  - 点击确认后，直接按 A2 第2步的方式切换页签浏览记录数据

#### 流程 B：医保机构查询（纯搜索）

适用于查询医保定点医疗机构、定点零售药店、医保经办机构、医疗机构（门诊）。**在执行 GUI 操作前，必须先按第零步的「医保机构子服务澄清」规则向用户确认具体要查什么。**

##### B1. 确认查询信息

在导航之前，先向用户确认要查的机构或药店名称和查询范围。

**根据子服务类型采用不同的名称策略：**

- **定点医院 / 医疗机构（门诊）查询**：用户可提供医院名称（全称或简称均可），系统会先尝试补全为全称搜索，若无结果则提取关键词模糊搜索。
  → 用户说"中山三院" → 扩展为"中山大学附属第三医院"搜索；搜不到则提取"中山"模糊搜索
  → 用户说"广东省人民医院" → 直接用全称搜索
- **定点药店查询**：用户可提供药店名称（全称或简称均可），提取核心关键词进行模糊搜索。
  → 用户说"大参林药店" → 提取关键词"大参林"进行模糊搜索
  → 用户说"同仁堂" → 直接用"同仁堂"进行模糊搜索
- **医保经办机构查询**：不需要机构名称，只需要确认用户所在的**区域**（如"天河区"、"广州市"），后续在搜索框中直接输入区域名称即可。如用户要求查全广州，则跳过搜索步骤直接采集当前页面数据

回复模板：

```
定点医院 / 医疗机构（门诊）：'请问要查哪家医院或门诊？提供名称即可（支持简称、模糊搜索），例如"中山三院"、"广东省人民医院"'
定点药店：'请问要查哪家药店？提供名称即可（支持模糊搜索），例如"大参林"、"同仁堂"'
医保经办机构：'请问您要查哪个区域的医保经办机构？例如"天河区"、"越秀区"或"全广州"'
```

- 如果用户输入时已明确名称，跳过询问
- **同时识别区域/位置信息**：如果用户提到"附近"或具体行政区域（如"广州天河区"、"附近的医保机构"），需识别并记录该区域信息，作为后续 B3 位置筛选的依据

##### B2. 导航到医保机构查询页面

回到穗好办首页 → 点击首页搜索框 → 输入"定点医疗机构查询"或"定点零售药店查询"或"医保经办机构查询"或"医疗机构（门诊）查询"（根据用户确认的子服务选择对应关键词）→ 在搜索结果中点击最匹配的服务卡片 → 进入查询页面

##### B3. 位置/区域筛选

**根据子服务类型采用不同的策略：**

**定点医院 / 定点药店 / 医疗机构（门诊）查询**——使用页面位置筛选控件：

当用户查询涉及"附近的"或具体行政区域（如"广州天河区"）时，**必须先在查询页面进行位置筛选**，然后再在搜索框中输入机构名称：

1. **点击位置筛选**：在查询页面左上角找到位置筛选入口并点击
2. **轻微滑动选择区域**：下方会弹出半模态弹窗，在弹窗中**轻微滑动**时间滚条，将目标城市/行政区域滑到中间高亮区域（不要直接滑到底部），确保精准选中
3. **点击确认查询**：完成区域选择后点击"确认"按钮应用位置筛选
4. **检查医保机构名称**：位置筛选完成后，检查 B1 中是否已获取到机构名称
   - **已获取名称**（如"广州市天河区人民医院"）：**去掉名称中已包含的区域前缀**，仅保留区域之后的字样作为搜索关键词。例如"广州市天河区人民医院" → 提取为"人民医院"。然后进入 B4 用提取后的关键词搜索
   - **缺少名称**（如只说了"查一下广州天河区的医保机构"）：向用户询问具体要查的机构名称
     - **定点医院 / 医疗机构（门诊）**："已按您要求筛选了[区域]的医保机构，请问要查哪家医院或门诊？提供名称即可（支持简称、模糊搜索）。"
     - **定点药店**："已按您要求筛选了[区域]的医保机构，请问要查哪家药店？提供名称即可，支持模糊搜索。"
       用户回复名称后，再进入 B4 输入搜索
- **若查询无"附近"或区域要求**（如"广东省人民医院"）：跳过本步骤，直接进入 B4

**医保经办机构查询**——不使用页面位置筛选控件，直接在搜索框输入区域名称：

1. 根据用户指定的区域提取区域关键词（如"天河区"→"天河"，"越秀区"→"越秀"）
2. **如果用户要求查全广州的医保经办机构**：**跳过搜索步骤**，直接在当前页面上采集所有已显示的数据，汇总返回
3. **如果用户指定了具体区域**：在搜索框中输入提取后的区域关键词（如"天河"），点击搜索，浏览并记录所有返回的结果

##### B4. 在搜索框中输入查询

在当前页面的搜索框中输入 B1 或 B3 中获取到的关键词，点击搜索按钮，浏览搜索结果，记录返回的数据。

**根据子服务类型采用不同的搜索策略：**

- **定点医院 / 医疗机构（门诊）查询**：
  - **策略一（补全全称）**：若用户输入的是常见简称（如"中山三院"→"中山大学附属第三医院"，"省医"→"广东省人民医院"），先在搜索框中输入补全后的全称搜索
  - **策略二（关键词提取）**：若补全全称搜索无结果，或用户输入的是名称片段（如"中山大学医院"→提取"中山大学"），则提取核心关键词进行模糊搜索
  - **策略三（汇总列表）**：模糊搜索后如有多个结果，**每一条都要完整记录下来**，汇总列表后返回给用户。如果列表太长（超过10条），记录前10条并提示用户可以缩小范围
- **定点药店查询**：用提取的核心关键词进行模糊搜索。会返回一个结果列表，**每一条都要完整记录下来**，汇总列表后返回给用户。如果列表太长（超过10条），记录前10条并提示用户可以缩小范围
- **医保经办机构查询**：
  - 用户指定区域：在搜索框中输入区域关键词（如"天河"），点击搜索，浏览并记录所有返回的结果
  - 全广州查询：不输入搜索词，直接采集当前页面已显示的所有数据

##### B5. 输出医保机构查询结果

### 第三步：综合查询处理

当用户同时要求查询多项服务时：

1. **按优先级依次执行**：社保 → 医保机构
2. **逐项输出结果**：每项查询完成后输出对应的结果

## 一次性原则

每次调用 `xiaoyi_gui_agent` 时，query 中只能包含**一个明确的查询目标**。

- 如果用户要求查某个月/某个范围，query 中的时间设置、查询、数据读取必须一次性完整描述
- ❌ 禁止在 gui agent 返回结果后，追加额外操作指令（如改时间、再查其他月份、点击搜索、滑动翻页等）——这会误导 agent 继续操作页面而非分析已有结果
- ✅ gui agent 返回数据后，直接分析整理结果输出即可，不要做任何多余的点击或其他操作
- ✅ 如需查询另一个条件或时间段，单独发起一次新的 gui agent 调用

## query 完整性原则

query 中的指令必须包含完整的操作步骤，不能因为追求简短而省略关键动作。

- ❌ 错误示例："查2022年10到11月，养老/工伤/失业"——gui agent 可能只看了默认首页（养老页签）就返回
- ✅ 正确示例："设时间2022年10月到11月，点确认，然后**依次切换养老、工伤、失业三个页签**，逐页浏览并记录每一页的数据"
- 关键动作指令（如切换页签、滑动浏览等）不能因为怕超时而省略，否则返回的数据会不完整

## 注意事项

1. **模拟操作的边界**：`xiaoyi_gui_agent` 工具负责实际的手机端 GUI 模拟操作。本 Skill 负责任务编排、意图识别和结果处理，不直接执行 GUI 操作。
2. **等待时间**：GUI 模拟操作（如 App 启动、页面加载、数据查询）需要合理的等待时间，不要在一步操作后立即执行下一步，应等待画面渲染完成。
3. **异常处理**：如果在任何步骤遇到异常（如 App 闪退、网络超时、页面找不到目标元素），应尝试重试 1-2 次，仍然失败则向用户报告具体错误信息。
4. **隐私保护**：查询结果包含个人敏感信息，在对话中展示时注意不要在公共场合泄露。保存到本地文件时提醒用户注意文件安全。
5. **登录状态的判断**：通过检测页面上是否出现"登录/注册"、"华为一键登录"等按钮来判断未登录状态。
6. **默认查询范围**：社保查询默认最近半年。医保机构查询无时间范围概念。
