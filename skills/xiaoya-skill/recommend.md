# recommend — 个性推荐

根据你的收听习惯与兴趣偏好，为你推荐可能喜欢的有声内容。

## 工具列表

| 工具名 | 说明 | 典型场景 |
|--------|------|----------|
| `get_personalized_recommendations` | 个性化推荐 | 基于用户画像推荐内容 |
| `batch_find_similar_albums` | 批量查询相似专辑 | 批量推荐相似专辑 |

## get_personalized_recommendations

**功能**：基于用户画像生成个性化推荐。

**请求参数：**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `size` | integer | 否 | 推荐数量，最大20 |
| `contentType` | string | 否 | `all`（默认）/`album`/`track` |

**回包**：格式化文本，个性化推荐结果。

示例：
```
个性化推荐结果（用户ID：123）

【推荐卡片1：为你推荐的音乐专辑】
卡片类型：专辑推荐
推荐理由：根据你的收听偏好为你推荐

推荐内容（共5个专辑）：
1. {专辑名:xxx;专辑ID:123;...}
   推荐分数：8.5

推荐统计：
- 总推荐卡片数：2
- 推荐专辑总数：5
- 推荐声音总数：5
```

## batch_find_similar_albums

**功能**：批量查询相似专辑。

**请求参数：**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `albumIds` | string[] | 是 | 专辑ID列表 |

**回包**：格式化文本，批量相似专辑查询结果。

示例：
```
相似专辑查询结果（共查询 2 个专辑）：

【查询专辑1】
原专辑：{专辑名:xxx;专辑ID:123;...}

相似专辑（最多10个）：
1. 相似度：8.5 | {专辑名:yyy;专辑ID:456;...}

查询统计：
- 总查询专辑数：2
- 成功查询数：1
- 失败查询数：1
- 返回相似专辑总数：5
```

## 工作流

1. 用户问"首页推荐" → `get_personalized_recommendations`
2. 用户问"给我推荐类似的" → `batch_find_similar_albums`
3. 展示推荐结果：编号列表，展示标题、主播、播放量、分类；附上跳转链接（客户端根据实际环境选择 `iting://` 或网页链接）

## 数据展示规范

- **内部标识不得暴露**：回包中的 `专辑ID`、`声音ID`、`用户ID` 等内部标识仅用于内部上下文记忆或构造深度链接，**面向用户展示时不得主动以纯文本形式暴露**。重点展示标题、主播、播放量、分类、推荐理由等用户感知度高的信息
