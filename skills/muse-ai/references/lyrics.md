# 歌词创作专家（MuseAI）

专注歌词文本质量：文字表达、叙事结构、情感共鸣、格式技巧、中文咬字和迭代决策。完整标记体系、Style 工程和人声标签分级见 `references/arrangement.md`。

**一条底层约束**（写词最容易踩）：结构与人声标签（`[Verse]`、`[Chorus]`、`[Female]`）**只放在歌词字段**，用英文方括号、独占一行；**绝不要塞进 Style 风格字段**（Style 只用逗号分隔的描述词）。字段职能分工见 `references/arrangement.md`。

## 歌词文本方法论

### 段落叙事功能

各段承担不同叙事职责，理解功能才能写出结构合理的歌词：

- **Verse（主歌）**：叙事主力，每段推进故事或展现新层面。多段 Verse 必须有情感/信息递进——重复同一内容是单调的首因。
- **Pre-Chorus（导歌）**：从叙述态转向情感爆发的桥接，制造期待。短而有张力。
- **Chorus（副歌）**：全曲情感核心与记忆点。简洁有力，2-4 行为宜；**每次出现都完整写出歌词**，不要写"重复副歌"占位（引擎不理解）。
- **Bridge（桥段）**：打破重复，引入新视角或情感转折。常置于最终副歌前蓄力。
- **Outro（尾声）**：情感收束——余韵、呼应开头、或渐远意象。

### 反套路写法（写出不平庸的词）

AI 是概率引擎，正向提示默认拉向最通俗的输出。在歌词层面对抗"平庸"：

- **禁用陈词**：`touch the sky`、`never give up`、`chase my dreams`、"飞翔/梦想/光芒"一类口号化短语。
- **替代策略**：第一人称视角 + 具体场景 + 动作性细节，取代抽象励志。"凌晨四点便利店的关东煮"比"追逐梦想不放弃"有画面。
- **单一核心隐喻**：全曲围绕一个主导意象展开，避免多个意象互相稀释。
- **每行限词**：英文每行约 4-6 词、中文 6-10 字，给旋律留空间，也减少"急唱"（rushed）。这是缓解急唱的经验区间，不是硬规则——**同段各行长度尽量一致**比精确字数更重要。

## 格式化技巧

这些手法直接影响引擎的演唱方式。注意：它们是**倾向性引导**，效果受流派/节拍/上下文影响，不是工程级精确控制。

**元音延长 / 连字符**（多源验证有效）——延长音符时值，制造花腔（melisma）：
```
lo-o-o-ove      → 延长 "love"，适合副歌高潮
to-night        → 两音节各获更多时值
yeaaah / ohhhh  → 比连字符更口语，适合 ad-lib / 结尾渐弱
```
适合副歌高潮，节制使用。配合 Style 写 `laid-back delivery` 可进一步缓解急唱。

**大写强调**——全大写让 AI 以更大力度/更高能量演唱：
```
NOTHING CAN BREAK US NOW
```
注意：汉字无大小写，**ALL CAPS 对中文基本无强调作用**（合理推断，缺直接实测）——中文改用感叹号、叹词（啊/哦）或 `[Belting]` 标签。

**标点控时**（影响真实，但属"倾向"而非"精确"）：

| 标点 | 效果 |
|------|------|
| 句号 `.` | 完整停顿，音高重置 |
| 逗号 `,` | 短暂气口，维持乐句流动 |
| 省略号 `...` | 拖长/犹豫/啜泣式呼吸，制造悬念 |
| 破折号 `—` | 突然截断/情绪转折，或延长音节 |
| 感叹号 `!` | 推进能量，更大力度 |
| 问号 `?` | 语调上扬 |
| 换行（单独换行） | 较长乐句停顿——行与行之间的断点 |
| 空行 | 人声停、器乐续（比换行更大的留白） |

过量重标点会扰乱节拍，需适度。

## 圆括号系统：和声 / ad-lib / 演唱指令

圆括号 `( )` 中的文字作为行级内容与主旋律交互。**关键认知：圆括号不保证内容被唱或不被唱，行为是概率性的**（社区估约 70% 遵从）。两类用途要区分清楚——这是写词最容易误判的地方。

**A. 作为演唱内容（和声 / ad-lib / call-response）——会被唱出**

完整歌词短句放括号内通常会被演唱，这正是 ad-lib 的惯用写法。核心是决定**括号里写什么词**：

*回声* — 重复主旋律关键词，制造空间感：
```
Sing me a song (sing me a song)
We rise (rise!) above it all (all!)
```
*对话式 ad-lib* — 插入新词，制造多层次对话：
```
My dream (only you!) will remain with me
```
*情感强化* — 副歌高潮叠加和声词增厚：
```
We are UNSTOPPABLE (unstoppable!)
```
要点：括号内 ad-lib **越短越稳，1-3 词最可靠**（回声/感叹短词，如 `(rise!)`、`(me, me)`），最多不超过 3-5 词——多于此易抢拍当主旋律或被略过。副歌中最有效，Verse 节制使用，可配 `[Harmonies]` 标记。

**B. 作为演唱指令（声音方向）——大概率不被唱出**

仅当满足"1-3 词 + 独占一行"时，模型才倾向把它解读为方向而非歌词：
```
(softly, almost whispering)
I'll find you in the dark
```
合法指令词：`(softly)`、`(whispered)`、`(building)`、`(powerful)`、`(belted)`。全曲不超过 2-3 个。

**绝对不想被演唱时**，不要只靠圆括号——用 `[Instrumental Break]` 或独占行的方括号标签。

> 花括号 `{ }` 控制和声是**迷思**（约 50% 模糊合规、单一来源）。和声用 `[Harmonies]` / `[Backing Vocals]` + Style 描述词。

## 歌词内人声标记与歌词配合

> 完整人声标签可靠性分级（Tier 1-4）属 arrangement reference 范畴。本节聚焦标签**与歌词文本如何配合**。

**铁律：标签独占一行**，前后不附歌词文本，否则会被唱出来：
```
✓ 正确              ✗ 错误
[Verse 1]          [Verse 1] Walking down the street
Walking down...
```
未加方括号的指令词（直接写 `Whisper`）会被当歌词唱出"whisper"这个词。

**两条与歌词搭配的可靠性要点**（完整分级见 arrangement reference）：
- `[Falsetto]` 等 Tier 2 标签单用成功率仅约 50-60%，**必须在 Style 字段同时写**对应描述词（`natural falsetto, airy high register`）才稳。
- **任何"标签:数值%"格式（`[Reverb: 30%]`、`[AutoTune: 60%]`）是 100% placebo**，MuseAI 不解析参数。效果描述放 Style 字段。

## 性别 / 对唱 / 合唱的歌词写法

> 人声编排机制（Tier、无真正对位、声部漂移）见 arrangement reference。本节聚焦**怎么写好对白歌词**。

**逐行标注说话者**——每行都标，不能只在段顶标一次（否则声部漂移）：
```
[Verse 1]
[Female] 你说时间会带走所有
[Male] 可我还站在原地等候
[Both] 而风继续吹过我们的街口
```
写好对唱词的要点：
- **两个声部要有视角对比**，不是把一段词随机劈成两半——男声叙事、女声回应，或一问一答。
- 节段保持 **8-12 行以内**，过长声部会崩塌。
- **Lead + Ad-libs 模式比完整对唱更稳**：主唱完整句，行内圆括号写 1-3 词的回声/ad-lib（括号里**直接写要唱的词**，如 `(不回头)`、`(oh yeah)`，别写 `echo`/`adlib` 标签词，否则会被唱出来）。
- 真正的对位双声部（两条同时独立旋律）写不出来，会崩塌——用交替轮唱或呼应近似。

**Call-and-Response（一问一答）的写词要点**：要写成**真正的问→答呼应**（女问、男答，每句承接上句），而非"女→男→合"的顺序叙事，更不是把一段词劈成两半的伪对唱。逐行标说话者的标记模板与 `antiphonal vocals` 触发词见 arrangement 人声编排（那是该机制的权威）。

## 中文 / 非英语歌词咬字与对策

MuseAI 默认生成英文。中文歌词若不处理，常见"英文化、跑调、咬字怪、多音字读错"。以下是成体系对策。

**⓪ 正向咬字提示**（最对症、最低成本，与下面各条互补）：咬字怪/吞字时，**在 Style 字段加正向演唱质量词** `clear pronunciation, clean delivery, tight phrasing`（需音准时再加 `pitch perfect, in tune vocals`），用正向描述拉清晰度，比只靠负面限制有效。这是中文"咬字怪"的第一手段，再叠加下面的汉字优先/谐音替换。

**① 必做：显式指定语言**（在 Style 字段）：`singing in Mandarin Chinese` / `Mandarin vocals`，与曲风组合：`Mandopop ballad, emotional male vocals singing in Mandarin Chinese`。防漂移加 `All lyrics in Mandarin Chinese, no English`。避免只写 `Chinese music`（太宽泛，可能生成中国元素的英文歌）。

**② 用汉字，不用拼音**：歌词字段直接输入汉字。汉字保留声调信息，处理精度高于拼音；拼音字母会被当英文发音处理而混乱。

**③ 多音字 → 谐音字替换法**（社区验证最有效）：把读错的多音字换成同音常用字。**"同音"指声母+韵母+声调完全相同**（不是近音）——替换字若声调不同会引入新的跑调；选字优先笔画简单、避免引入新的多音字。

| 原字 | 易误读 | 替换（同音同调） |
|------|--------|--------|
| 朝(zhāo) | cháo | 招(zhāo) |
| 还(huán) | hái | 环(huán) |
| 重(chóng) | zhòng | 崇(chóng) |

优点：不影响演唱连贯；缺点：自动字幕显示替换字。

**④ 行长与标点**：单段 4-8 行，每行 6-10 个汉字，同段各行字数差控制在 ±1-2。行尾慎用中文句号/逗号（多用换行），但完全无标点会致仓促演唱，需在合适处保留逗号或空行。避免生僻字、文言专字（兮/乎/矣），密集仄声处易崩，适当拆行。**急唱/吞字**时，「格式化技巧」里的延音/呼吸手段对汉字同样适用：对情感字用破折号延音（`爱——`、`想——`）、用省略号制造呼吸，并在 Style 加 `slow tempo, laid-back delivery`。

**⑤ 粤语**（不稳定，需辅助）：粤语未列入官方"最佳支持"，9 声调易被普通话拼读。最有效是**粤拼（Jyutping）注音法**——用 LLM 把歌词转粤拼标注后粘入歌词字段，Style 写 `Cantopop, Cantonese vocal`。建议繁体输入，多生成 3-5 次选优。**结果须听辨校验**：即便用尽这些方法，仍可能漏出普通话音节——生成后逐句听辨声调对错，不达标就换字/重注音再生成，不要默认一次到位。

**⑥ 中英混排**：先稳定纯中文版（确认不漂移），再把需英文演唱的行改为英文（建议英文放 Chorus/Hook、中文放 Verse），Style 注明分布 `verse in Mandarin, chorus hook in English`。避免同一行内中英混合（除非刻意说唱）。

> 注：括号拼音注音法（`还 (huán)`）为旧版用法，现已转向"汉字优先 + 谐音替换"，注音成功率下降，不宜首选。**确需用拼音时，必须带声调数字**（如 `ni3 hao3`）——不带声调的裸拼音会被当英文读、跑调最严重。"MuseAI 将支持 8 种中文方言"无官方依据，系误传。

## 歌词字符上限

歌词走 `--mode custom` 的 `--description`（等价别名 `--lyrics`）字段。

- **字符上限未被官方逐一文档化**：社区常引「Custom 5000 字符」（更早的「3000」是旧规格误引），但 `muse` CLI 对 custom 模式只校验歌词**非空**、不按字数硬截断，内容按原样提交。把 5000 当**参考量级**而非确认硬阈值，存争议处以实际生成返回为准。
- 引擎侧若内容过长仍可能**静默截断、无警告**——最重要的内容前置、留余量。
- 经验性软建议（**按英文字符计**）：篇幅约 **2000-3500 字符**通常更稳，避免段落被压缩/跳过（社区经验，非实测硬阈值）。**中文/CJK 按码点计数（1 个汉字 = 1 个字符），不要套用这个英文区间**：一首完整中文歌按「单段 4-8 行 × 每行 6-10 字」（见中文咬字 ④）推算通常仅几百字，远低于该区间属正常，不必为凑字数硬扩写——硬扩反而触发引擎压缩/跳段。

## 歌词迭代协议（何时自己改 / 何时调引擎）

**迭代前置心法（先读，决定要不要重生成）**：

- **弱底稿不靠重生成救活**：立意陈旧、叙事混乱、副歌无记忆点的词，刷多少次也只是不同版本的平庸。先把**文本本身改强**再生成；重生成只在底稿过硬时才提升命中率。
- **每次只改一个变量**：一次只动「改词」或「调 Style」或「换标签策略」中的一项，否则下一版变好/变坏都无法归因。
- **单次生成是概率性的**：同一份词不同次差异可能很大，「产 3-5 版选优」是**默认动作**而非失败补救——别把一次跑偏当成词写错而过度雕琢文字。
- **止损**：同一问题用同一 prompt 连刷 2-3 次仍不中，不要原地继续刷，换方法（改文本 / 调 Style 描述 / 换标签策略）。前期把词打磨精准比靠多次重生成赌中更省额度、收敛更快。

判断一个问题该改歌词文本、还是该靠重新生成，是高效迭代的关键：

- **纯文本问题 → 自己改歌词重生成**：用词陈旧、叙事不清、副歌不抓耳、行长不齐、多音字读错、标点节奏不对。这些都在文字层面，改完重新生成。
- **跑调 / 咬字 / 声部崩塌 → 主要靠重新生成**：MuseAI 无音准校正工具，跨次生成差异明显。先排查是否流派标签与音准期望冲突（indie/folk/lo-fi 本身含"真实感微偏音"美学），Style 加 `pitch perfect, in tune vocals, clear pronunciation`，再生成 3-5 次选优。
- **大部分已好、个别段落有问题 → 只改该段歌词后重新生成**，多生成几次保留满意版本。
- **结构 / 编曲层面问题**（加 Interlude、Build→Drop、段落重排、换风格）→ **配合 arrangement reference**。

## 版本快照管理

- 每次展示歌词标注版本号：**v1**、**v2**、**v3**……
- 版本变更注明改动摘要，如"**v2**：重写副歌，新增 Bridge，加入和声标注"。
- 支持版本混搭：用户说"用 v1 的主歌 + v2 的副歌"，你负责正确拼接。
- **每次重生成都要重申 Style 锚点防漂移**：MuseAI 每次生成无状态，混搭拼接、改某段后重生成时若不重新带上原 Style（流派/调性/速度/不引入新乐器），流派或人声身份会整段漂移——v1 主歌与 v2 副歌本可能来自不同 Style 走向，漏掉重申会让拼出的"最终版"听感割裂。锚点写法配合 arrangement reference。
- 提交生成前，展示完整**最终版**供用户确认。
- 建议每次生成产出 **3-5 个版本**选优（生成间差异较大，单次生成是概率性失败）。

## 歌词展示规范

- **保留所有结构标记**，让用户看到完整编排。
- 首次展示时，对关键段落做简短注解（如"↑ Bridge 这里做了情感转折，打破前面重复"），只在有意义处加，不必每段。

## 歌词优化建议

当用户有歌词需要优化时，依次检查：

1. **结构完整性**：有 Pre-Chorus 吗（缺则过渡生硬）？有 Bridge 吗（缺则重复感强）？有 `[Outro]` + `[End]` 吗（缺则突然截断——约 90% 截断问题根因在此）？
2. **副歌质量**：朗朗上口、有重复旋律感吗？核心金句够简短吗（2-4 行）？每次副歌都写全了吗？
3. **文字质量**：有没有陈词滥调可以换成具体场景？是否围绕单一核心隐喻？
4. **和声与 ad-lib**：副歌可加圆括号和声增厚吗？有适合 ad-lib 的位置吗（Post-Chorus）？
5. **格式化**：高潮关键词可用元音延长/大写增强吗？标点是否合理控制了节奏？每行长度是否一致（防急唱）？
6. **人声变化**：Bridge 用 `[Soft]`/`[Falsetto]`（需 Style 铺垫）制造反差？最后一遍副歌用 `[Belting]` 推高潮？
7. **中文专项**（若为中文歌）：语言指定了吗？多音字处理了吗？行尾标点克制吗？
8. **编曲层面调整**（加 Interlude、段落重排、风格定义）→ 配合 arrangement reference。

## 需废弃的迷思（速查）

| 迷思 | 真相 |
|------|------|
| 圆括号"保证"内容不被唱 | 概率性（约 70%）。完整短句通常被唱（=ad-lib），仅 1-3 词独占行才倾向不唱 |
| 花括号 `{ }` 控制和声 | 无验证、单一来源，废弃。用 `[Harmonies]` + Style |
| `[Reverb: 30%]` 等参数标签有效 | 100% placebo，效果放 Style 字段 |
| 中文用拼音输入更好 | 已确认汉字优于拼音，拼音引发英文化 |
| 拼音括号注音仍最优 | 现已转向谐音字替换法，注音成功率下降 |
| 中文标点不影响演唱 | 标点直接影响演唱节奏，行尾标点需克制 |
