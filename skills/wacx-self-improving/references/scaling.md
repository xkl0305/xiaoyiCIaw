# 扩展模式

## 体量阈值

| 规模 | 条目数 | 策略 |
|------|--------|------|
| 小 | <100 | 单 memory.md，不命名空间化 |
| 中 | 100-500 | 拆分为 domains/，基础索引 |
| 大 | 500-2000 | 完整命名空间层级，积极压缩 |
| 巨 | >2000 | 按年归档，热层只留摘要 |

## 何时拆分

当出现以下情况时，创建新命名空间文件：
- 单文件超过 200 行
- 某主题有 10+ 条不同纠正
- 用户明确区分上下文（"工作上……"、"这个项目里……"）

## 压缩规则

### 合并相似纠正
```
之前（3 条）：
- [02-01] 用 Tab 而非空格
- [02-03] 用 Tab 缩进
- [02-05] 请用 Tab 缩进

之后（1 条）：
- 缩进：Tab（确认 3 次，02-01 至 02-05）
```

### 摘要冗长模式
```
之前：
- 给 Marcus 写邮件时用要点，控制在 5 条以内，
  不用行话，先说结论，他偏好上午发送

之后：
- Marcus 邮件：要点 ≤5、无行话、BLUF、偏好上午
```

### 带上下文归档
移入冷层时：
```
## 已归档 2026-02

### 项目：old-app（自 2025-08 起不活跃）
- 用过 Vue 2 模式
- 偏好 Vuex 而非 Pinia
- CI 在 Jenkins（已弃用）

原因：项目完成，模式不太可能再适用
```

## 索引维护

`index.md` 追踪所有命名空间：
```markdown
# 记忆索引

## 热层(HOT，始终加载)
- memory.md：87 行，更新于 2026-02-15

## 温层(WARM，匹配时加载)
- projects/current-app.md：45 行
- projects/side-project.md：23 行
- domains/code.md：112 行
- domains/writing.md：34 行

## 冷层(COLD，归档)
- archive/2025.md：234 行
- archive/2024.md：189 行

上次压缩：2026-02-01
下次计划：2026-03-01
```

## 多项目模式

### 继承链
```
全局 (memory.md)
  └── 领域 (domains/code.md)
       └── 项目 (projects/app.md)
```

### 覆盖语法
在项目文件中：
```markdown
## 覆盖
- 缩进：空格（覆盖全局 Tab）
- 原因：项目 eslint 配置要求空格
```

### 冲突检测
加载时检查冲突：
1. 构建继承链
2. 检测矛盾
3. 最具体的胜出
4. 记录冲突供后续复核

## 用户类型适配

| 用户类型 | 记忆策略 |
|----------|----------|
| 高级用户 | 积极学习，最少确认 |
|  casual 用户 | 保守学习，频繁确认 |
| 团队共享 | 每用户命名空间，共享项目空间 |
| 隐私优先 | 仅本地，按类别逐类明确同意 |

## 恢复模式

### 上下文丢失
若智能体在会话中途丢失上下文：
1. 重读 memory.md
2. 检查 index.md 寻找相关命名空间
3. 加载活跃项目命名空间
4. 用恢复的模式继续

### 损坏恢复
若记忆文件损坏：
1. 在 archive/ 中查找近期备份
2. 从 corrections.md 重建
3. 请用户重新确认关键偏好
4. 记录事件用于调试
