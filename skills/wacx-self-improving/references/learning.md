# 学习机制

## 什么触发学习

| 触发 | 置信度 | 动作 |
|------|--------|------|
| "不对，改做 X" | 高 | 立刻记录纠正 |
| "我之前跟你说过了……" | 高 | 标记为重复，提升优先级 |
| "永远/绝不 X" | 已确认 | 晋升为偏好 |
| 用户编辑你的输出 | 中 | 记为试探性模式 |
| 同一纠正 3 次 | 已确认 | 询问是否永久化 |
| "对于这个项目……" | 限定范围 | 写入项目命名空间 |

## 什么不触发学习

- 沉默（不是确认）
- 任何单一实例
- 假设性讨论
- 第三方偏好（"John 喜欢……"）
- 群聊模式（除非用户确认）
- 隐含偏好（绝不推断）

## 纠正分类

### 按类型
| 类型 | 示例 | 命名空间 |
|------|------|----------|
| 格式 | "用要点而非段落" | 全局 |
| 技术 | "用 SQLite 而非 Postgres" | 领域/代码 |
| 沟通 | "消息短一点" | 全局 |
| 项目专属 | "这个仓库用 Tailwind" | projects/{name} |
| 个人专属 | "Marcus 要 BLUF（先说结论）" | 领域/沟通 |

### 按范围
```
全局：处处适用
  └── 领域：适用于某类别（代码、写作、沟通）
       └── 项目：适用于特定上下文
            └── 临时：仅本会话适用
```

## 确认流程

3 次相似纠正后：
```
智能体："我注意到你更偏好 X 而非 Y（已纠正 3 次）。
        要我永远这样做吗？
        - 是，永远
        - 仅限 [上下文]
        - 否，具体问题具体分析"

用户："是，永远"

智能体：→ 移入已确认偏好
       → 从纠正计数中移除
       → 此后使用时标注来源
```

## 模式演化

### 阶段
1. **试探** —— 单次纠正，观察是否重复
2. **浮现** —— 2 次纠正，疑似模式
3. **待确认** —— 3 次纠正，请求确认
4. **已确认** —— 用户批准，除非被撤销否则永久
5. **已归档** —— 90+ 天未用，保留但停用

### 撤销
用户随时可撤销：
```
用户："其实我对 X 改主意了"

智能体：
1. 归档旧模式（保留历史）
2. 带时间戳记录撤销
3. 把新偏好作为试探性加入
4. "知道了。我现在改做 Y。（之前：X，已归档）"
```

## 反模式

### 绝不学习
- 如何让用户更快顺从（操控）
- 情绪触发点或弱点
- 来自其他用户的模式（即便共享设备）
- 任何浮现出来让人"不适"的东西

### 应避免
- 从单一实例过度泛化
- 学风格胜过学实质
- 假设偏好稳定
- 忽略上下文变化

## 质量信号

### 好的学习
- 用户明确陈述偏好
- 模式跨上下文一致
- 纠正改善了结果
- 用户在被问时确认

### 坏的学习
- 从沉默推断
- 与近期行为矛盾
- 只在狭窄上下文成立
- 用户从未确认
