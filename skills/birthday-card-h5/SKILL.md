# 生日祝福H5贺卡生成

## 工作流概览（四步）

```
Step 0. 问照片           → 用户提供？分析照片内容 / 不提供？全部AI生图
Step 1. 定文案           → 6句祝福语（2句/页），有照片则基于照片内容贴合生成
Step 2. 生素材（并行）    → 6张插图 + 1首钢琴+木吉他BGM
                           有6张照片→直接使用
                           有N张照片(<6)→前N张用原版，后6-N张用风格转换补充
                           无照片→全部AI生图
Step 3. 合成HTML          → 运行 generate_h5.py 产出单HTML
```

## Step 0: 询问照片

**用户发出生日贺卡诉求后，必须先问："你有照片想放进去吗？可以把照片处理成精美的效果~"**

### 情况A：用户提供照片

1. 接收用户提供的照片（1-6张均可）
2. **用户原始照片禁止缩放、禁止裁切**（强制规则）：
   - 所有用户上传的原始照片必须保持原始尺寸和原始质量完整嵌入
   - 不调用 PIL 进行 resize、crop 或任何尺寸修改
   - 仅允许做极轻微的色彩增强（可选，且不能降低画质）
   - 如果用户只有1张照片（🅰️方案全复用），6页全部使用原始照片的原始尺寸嵌入
   - 如果用户有6张照片，6页全部使用各自的原始照片完整嵌入
   - 如果用户有1-5张照片+风格转换补充，前N页原版照片保持原始尺寸，后6-N页的风格转换图是AI生成的（可缩放）

✅ **用户原始照片 → 直接以原始尺寸和原始画质嵌入HTML**
✅ 通过 `--no-resize` 参数控制，脚本自动将原照片以原始二进制编码为 base64 data URI，不做任何压缩

3. **用 `xiaoyi-image-understanding` 分析每张照片内容**（强制）：
   - 调用 image_reading 工具分析每张用户照片，获取照片的场景描述
   - 记录每张照片的：画面主体（人物/景物/动物等）、场景氛围、色彩基调、情绪感受
   - ⚠️ 每张用户照片都必须分析，分析结果将用于 Step 1 生成贴合照片的文案

4. **图片分配规则**（强制：用户照片禁止任何缩放、裁切或压缩）：
   - **6张照片** → 6页全部用各自的原始照片（原始尺寸、原始画质），依次对应P1-P6
   - **1-5张照片** → 前N页用用户原版照片（原始尺寸），剩余6-N页用**风格转换**补充（详见Step 2.1）
   - **1张照片** → 先询问用户选择方案：🅰️ 6页全部复用同一张照片（原始尺寸），🅱️ P1原版+后5页风格转换

### 情况B：用户不提供/没有照片

→ 跳过本步，Step 1 按随机文案规则生成，Step 2 全部用 AI 生成水彩插图。

## Step 1: 定文案

### 文案原则（强制）

**每次生成的文案必须有灵魂、不重复。**

文案生成分为两种模式：
- **照片模式**（用户提供了照片）：基于照片内容分析，生成与该页照片画面贴合的文案
- **标准模式**（无照片）：按原有随机规则生成通用温馨文案

---

### 照片模式（用户提供了照片时 -> 强制使用此模式）

**核心规则**：利用 Step 0 对每张照片的分析结果，为该照片量身定作文案。文案要"看图说话"，但保持生日祝福的温度。

1. **文案与照片画面贴合**：
   - 用 Step 0 中 image_reading 的分析结果来触发灵感
   - 例：照片是"两人在咖啡馆合影" → 文案可写"一起喝过的咖啡、聊过的天，都是最温暖的记忆 ☕"
   - 例：照片是"旅行风景" → 文案可写"走过的路、看过的风景，愿新的一岁带你去更多远方 🌄"
   - 例：照片是"宠物特写" → 文案可写"无论外面多累，回家总有毛孩子在等你 🐱"

2. **情绪延伸规则**：
   - 照片本身的情感氛围（温馨/欢乐/安静/浪漫等）决定该页文案的基调
   - 不要生硬地描述照片内容（"这是你在生日那天拍的蛋糕"），而要**从照片延伸到祝福**
   - 每页2句话：第一句从照片触发，第二句升华到生日祝福

3. **emoji点缀规则**：每页至少1个emoji，最多不超过2个，放在句尾或句首点缀。

**示例**（照片分析 → 生成的文案）：

| 照片内容 | 生成的文案（P1 开篇） |
|---------|-------------------|
| 两人聚餐合影 | "翻到这张照片，想起那天笑得有多开心。生日快乐，希望新的一岁，你身边永远有温暖的人陪伴 🎂" |
| 单人在海边 | "阳光、海浪，还有照片里你自在的笑。新的一岁，愿你心里有海，眼里有光，日子过得自由又精彩 🌊" |
| 宠物特写 | "每次看到这张照片都会不自觉地笑。世界有时很吵，但你的温柔和陪伴，比什么都珍贵 🐾" |
| 旅行风景 | "走过的路都成了风景，看过的风景都成了故事。愿新的一年，你的脚步能去到更多想去的地方 ✈️" |

**文案节奏**（6页要有情绪起伏）：
- P1：开篇祝福（从照片中最有代表性的画面切入，热情、直接）
- P2-P3：从照片细节延伸到情感回忆（细腻走心）
- P4-P5：友情/陪伴/美好瞬间（轻松、有共鸣）
- P6：收尾升华（温暖、有力、余味悠长）

4. **避免套路句**：禁止以下"AI感重灾区"表达：
   - ❌ "所有的美好都如约而至"
   - ❌ "愿你被这个世界温柔以待"
   - ❌ "前路漫漫亦灿灿"
   - ❌ "愿你的每一天都像~一样~"
   - ❌ "愿新的一岁，一切..."

---

### 标准模式（用户没有提供照片）

不依赖照片，按以下规则生成通用温馨文案：

1. **语气风格**（每页可不同，但整体协调）：
   - 温暖走心派 — "和你一起走过的日子，都是最好的时光"
   - 俏皮轻松派 — "又长大一岁啦，继续保持可爱"
   - 文艺诗意派 — "岁月漫长，然而值得等待"
   - 朴实真挚派 — "没什么大道理，就想你开开心心的"

2. **段落节奏**：
   - P1：开篇祝福（热情、直接）
   - P2-P3：温暖回忆或对生活的期许（细腻走心）
   - P4-P5：友情/陪伴/小确幸（轻松、有共鸣）
   - P6：收尾升华（温暖、有力、余味悠长）

3. **避免套路句**：同上规则

4. **emoji点缀规则**：每页至少1个emoji，最多不超过2个。

---

### 文案确认规则（两种模式均适用）

**生成文案后展示给用户确认才继续下一步。**

## Step 2: 生成素材

### 2.1 插图（6张）→ 按 Step 0 结果

取决于 Step 0 的选择：

**情况A：用户提供了6张照片**
→ 6页全部使用用户的原始照片（原始尺寸、原始画质），依次对应 P1-P6。不缩放、不裁切、不压缩。

**情况B：用户提供了N张照片（1-5张）**
→ 分两组处理：
- **前N页**：用 Step 0 处理后的**用户原版照片**，依次对应 P1-PN
- **后6-N页**：用 **Seedream 图生图风格转换**，基于用户的照片生成不同风格的变体
  - 从以下**风格池**中为每张补充图选择不同风格（每张不重复）：
    - 🎨 **卡通** (cartoon) — 明亮可爱的卡通风格
    - 🎨 **水彩** (watercolor) — 清新柔美的水彩插画
    - 🎨 **写实** (realistic) — 高保真写实摄影风
    - 🎨 **国潮** (guochao) — 中国风潮流插画
    - 🎨 **Q版** (q-version) — 萌系Q版可爱风
    - 🎨 **手绘** (hand-drawn) — 铅笔/钢笔手绘质感
  - **风格分配规则**：按风格池顺序顺次选取，确保每张不同
    - 例：用户给了2张照片，需要补充4张 → P3卡通/P4水彩/P5写实/P6国潮
  - **风格转换 prompt 模板**：
    ```
    # 将用户照片作为参考图，生成对应风格的变体
    # 保留照片的主要构图和主体（人物/景物/宠物等），改变绘画风格
    
    prompt = f"将这张生日照片转换为{风格名称}风格，保留原有的构图和主体，{风格描述}，画面温馨有生日氛围"
    ```
  - 使用 seedream-image-gen 的图生图能力：
    ```bash
    python3 skills/seedream-image_gen/scripts/generate_seedream.py \
      --prompt "将这张生日照片转换为卡通风格，保留原有的构图和主体，明亮可爱的卡通风格，画面温馨有生日氛围，16:9比例，高清细节" \
      --image /路径/用户照片.jpg
    ```
  ⚠️ **重要**：补充图片的 prompt 也要追加 "，16:9比例"，图片比例必须统一

- 每页补充的图片必须采用与主照片**不同的风格**，确保视觉丰富度
- 注意：用户原版照片保持原始尺寸，风格转换图由AI生成（16:9比例）

**情况C：用户给了1张照片**
→ **必须先询问用户选择哪种方案**：
  - 🅰️ 6页全部复用这张照片（原始尺寸、原始画质，6页用同一张原图不做任何修改）
  - 🅱️ P1用原版照片（原始尺寸），P2-P6用5种不同风格转换（推荐，视觉更丰富）

⚠️ **强制规则**：不得擅自替用户决定，必须等用户明确回复后再执行。

**情况D：用户不提供照片**
→ 全部用 Seedream 生成水彩插图（见下方prompt模板）

**Prompt模板**：用中文自然语言描述，包含"水彩画"或"水彩插画"，指定与文案情绪匹配的画面。

⚠️ **每张图的prompt必须随机化**：不要每次都用完全相同的描述。每次生成前先随机挑选以下变化组合，确保6张图在构图、角度、色彩氛围上有明显差异，不重复：
- **构图**（随机选1种）：居中特写 / 左侧三分法 / 右侧三分法 / 俯视视角 / 仰视视角 / 大全景 / 框架构图
- **光线氛围**（随机选1种）：柔和暖光 / 晨光熹微 / 黄昏余晖 / 月光清冷 / 午后阳光 / 烛光温馨 / 霓虹灯光
- **色彩基调**（随机选1种）：暖橘色调 / 粉蓝渐变 / 森绿自然 / 紫粉梦幻 / 金黄温暖 / 淡雅莫兰迪 / 清新马卡龙
- **额外元素**（随机选1-2种添加）：飘落的花瓣 / 闪烁的光斑 / 蝴蝶 / 小动物 / 星星点点 / 雾气朦胧 / 光影斑驳

每页推荐基础画面主题（prompt中的画面主体保持不变，但构图/光线/色彩/额外元素按上述规则随机化）：
- P1: 水彩插画，一个精美的生日蛋糕摆在铺着格子布的桌上，周围有彩色气球和星星装饰
- P2: 水彩插画，清晨的阳光透过窗帘洒进房间，窗台上放着一杯热茶和一本书
- P3: 水彩插画，宁静的夜空下漫天繁星，一个人坐在山坡上仰望星空
- P4: 水彩插画，两条蜿蜒的小路在花丛中交汇，远处是朦胧的青山
- P5: 水彩插画，午后阳光下的一只慵懒的小猫蜷缩在椅子上打盹
- P6: 水彩插画，一条开满野花的小路延伸向远方，阳光洒落

⚠️ **关键参数**：
- ⚠️ **图片比例强制为16:9**：每个 prompt 末尾必须追加 "，16:9比例"（例如 "水彩画风格，蛋糕烛光，16:9比例"）。`--width/--height` 参数不存在，不要使用。
- **图片质量要高**：在 prompt 末尾追加 "，高清细节丰富，高分辨率" 确保画质（放在"16:9比例"之前）
- 保存到 `workspace/generated-images/` 目录
- 输出文件命名规则：`YYYYMMDD_HHMMSS_SSS_XX_generated.jpg`
- 确认6张图全部生成完毕再进入下一步

每个prompt执行一次 `generate_seedream.py`，共6次。批量生成，不需要每张都问用户确认。

## Step 3: 合成HTML

### 3.1 运行脚本

**标准模式（通用文案）**：
```bash
python3 scripts/generate_h5.py \
  --images path/to/page1.jpg path/to/page2.jpg ...（6张图片路径）\
  --bgm path/to/bgm.mp3 \
  --name "祝福对象姓名" \
  --output /tmp/xxx.html
```

**照片模式（自定义贴合文案）+ 保留原图尺寸（用户照片时使用）**：
```bash
python3 scripts/generate_h5.py \
  --images path/to/page1.jpg path/to/page2.jpg ...（6张图片路径）\
  --bgm path/to/bgm.mp3 \
  --name "祝福对象姓名" \
  --texts "P1第一句文案" "P1第二句文案" "P2第一句文案" "P2第二句文案" "P3第一句文案" "P3第二句文案" "P4第一句文案" "P4第二句文案" "P5第一句文案" "P5第二句文案" "P6第一句文案" "P6第二句文案" \
  --no-resize \
  --output /tmp/xxx.html
```
- `--texts` 接收12个参数，按6页每页2句的顺序排列
- `--no-resize` 在用户提供原始照片时**必须添加**，确保原图完整尺寸嵌入

### 多设备适配规则（强制）

生成 HTML 中的 CSS 必须使用响应式设计，确保图片在手机、平板和 PC 等不同宽度的屏幕上显示合适大小，不在宽屏上显得过小：

- 手机（<768px）：图片宽度 `min(90vw, 420px)`
- 平板（768px-1023px）：图片宽度 `70vw`，最大 `580px`
- PC 小屏（1024px-1439px）：图片宽度 `65vw`，最大 `680px`，字体增大至 `22px`
- PC 大屏（≥1440px）：图片宽度 `50vw`，最大 `780px`，字体增大至 `24px`
- 文字容器最大宽度从 `360px` 提升为 `480px`
- 首页（splash）的标题、表情、按钮等元素在 PC 上也同步放大

该规则已经内置在 `generate_h5.py` 中，无需额外操作。

### 3.2 可选参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--name` | "小明" | 祝福对象姓名 |
| `--texts` | 无 | 12条自定义文案（每页2条，共6页），有照片时必填 |
| `--no-resize` | 关闭 | **开启后**保留用户照片原始尺寸、原始画质，不做缩放和压缩 |
| `--max-img-size` | 800 | AI生图/风格转换图的最大宽度（px），用户原图不受此参数影响 |
| `--quality` | 95 | 图片JPEG质量（AI生图使用），用户原图不受此参数影响 |
| `--bgm-duration-sec` | 0 | BGM截取秒数，0=完整嵌入 |
| `--output` | /tmp/birthday_card/index.html | 输出路径 |

### 3.3 图片质量规则（强制）

**用户原始照片（强制）：**
- 禁止任何缩放、裁切或压缩
- 必须使用 `--no-resize` 参数，将原始照片以原始二进制编码为 base64 data URI
- 合成HTML中的用户照片需严格等于用户上传时的原始尺寸和原始画质

**AI生成图片/风格转换图：**
- `--max-img-size` 使用 800px（保留细节）
- `--quality` 使用 95（高质量JPEG压缩）
- 禁止使用低于80的quality值

### 3.3 部署到云服务器（强制）

HTML 文件生成后，必须使用 **xiaoyi-web-deploy** 技能将生成的 HTML 部署到云服务器获取在线 URL，步骤如下：

1. 打包：`cd <项目目录> && zip -r project.zip index.html`
2. 上传：`python3 <xiaoyi-web-deploy技能目录>/scripts/upload_file.py project.zip`（获取 xiaoyiFileUrl）
3. 部署：`python3 <xiaoyi-web-deploy技能目录>/scripts/baas.py --x-api-type deploy --content-file-path <json文件>`
   - 如果没有现有 baas-config，先按 xiaoyi-web-deploy 规则创建 BaaS 应用
4. 将部署后的在线 URL 发送给用户
5. **HTML 文件交付规则（强制）**：
   - **默认情况**（用户只说"生成网页/贺卡/祝福页"，未主动要求文件）：只发送部署后的在线 URL，**不通过 `send_file_to_user` 发送 HTML 文件**。
   - **用户明确要求文件时**：才通过 `send_file_to_user` 将本地 HTML 文件发送给用户。

注意：每次重新生成 HTML 后都必须重新走一遍部署流程。

### 图片方向适配规则（强制）

合成HTML时，脚本会自动检测每张图片的宽高比，根据方向采用不同的展示方式：

- **横图/方图**（宽≥高）：使用 `aspect-ratio:16/9` + `object-fit:cover`，保持原有的铺满卡片效果
- **竖图/人像图**（高>宽×1.05）：使用 `object-fit:contain` 自适应高度，**完整显示整张图片**（人脸、头部和全身不会被裁剪），容器宽度缩小至 `min(65vw, 350px)`，最大高度限制为 `70vh` 确保不被屏幕裁掉

**竖图规则核心**：用户上传的竖版照片/自拍，必须保证人物头部不会被裁切，完整可见。

---

### 背景装饰规则（强制）

合成HTML时，每页背景必须在渐变底色上叠加对应的同款水彩插画作为透明装饰底图：
- 使用 `.bg-illus` 元素铺满页面背景，background-size: cover，background-position: center
- opacity 设置为 **0.2（20%透明度）**，确保文字清晰可读
- 添加轻柔呼吸动效（`bgBreathe`），opacity 在 0.18~0.25 之间渐变
- 添加 filter: saturate(0.7) blur(1px) 让背景更柔和
- pointer-events: none 避免干扰交互
