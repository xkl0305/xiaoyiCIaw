# 生日祝福H5 制作经验沉淀

> 从多轮调试中沉淀的经验，避免后人踩同样的坑。

## 1. 浏览器自动播放限制（最大坑）

**问题**：所有现代移动浏览器（Chrome、华为浏览器、Safari）都禁止**有声音频自动播放**。纯离线HTML（file://协议）尤其严格。

**解决方案**：首页"开始"按钮 + 用户点击触发播放。
- 用户点击 = 合法用户手势 → 浏览器允许play()
- 之后所有操作（自动翻页、滑动）都在播放状态进行

**已失败的方案**：
1. ❌ `<audio autoplay>` — 被浏览器拦截
2. ❌ `<audio autoplay muted>` + 立即 unmute — Chrome不允许
3. ❌ Web Audio API decodeAudioData + resume — 同样需要用户手势
4. ❌ base64超长data URI（3.7M字符） — 加载慢且不稳定
5. ❌ iframe + 各种hack — 浏览器政策不可绕过

## 2. 文件大小控制

**规则**：
- 单HTML文件越大，加载越慢，用户在手机上等不了
- 10MB+ → 明显卡顿，音频解码慢
- **推荐 < 5MB**

**⚠️ 用户原始照片禁止压缩（强制）**：
- 用户上传的原始照片必须以原始尺寸、原始画质完整嵌入，使用 `--no-resize` 参数
- 这意味着如果用户照片很大（如 4K/8K），合成后的HTML文件可能很大，这是**预期行为**
- 不应对用户原始照片做任何缩放、裁切或质量压缩

**BGM压缩策略**：
- 完整嵌入约 2.7MB（2分53秒），如果需要缩小用 `--bgm-duration-sec 120`（截取2分钟）
- 不截取最可靠（`--bgm-duration-sec 0`）

## 3. MP3截取的坑

**问题**：按字节截取mp3会破坏帧结构，导致播放卡顿、一段一段或直接不播。

**解决方案**：
- 不截取 → 完整嵌入最可靠（`--bgm-duration-sec 0`）
- 必须截取时用 `ffmpeg`（需要libmp3lame编码器），但云端沙箱不一定有
- 不要用文件头+随机字节截取方式

## 4. 图片渲染顺序

**关键**：`<img>` 必须优先渲染再触发动画观察器（IntersectionObserver）
- 把内容用JS插入（`innerHTML`）而不是HTML里直接写，避免加载顺序问题
- IntersectionObserver threshold 用 0.5（页面一半可见时触发文字浮现）

## 5. 自动翻页与用户交互

- 自动翻页用 `setInterval` + `scrollIntoView({behavior:'smooth'})`
- 用户手动触摸/滑动时清除 timer → 不会抢夺控制权
- 翻页间隔 5秒 比较舒适

## 6. Seedream 生图参数

- 水彩插图风格：prompt需明确"水彩画风格"
- 宽高比 `--width 3 --height 2` 适配手机竖屏
- 每次生成1张即可（不要一次多张，风格控制不好）
- 每张图prompt要配合文案情绪

## 7. MiniMax 音乐参数

- `--instrumental` 生成纯音乐（不要人声）
- prompt：描述乐器+情绪+风格（如"钢琴+木吉他"+"温暖/舒缓/治愈"）
- 每次生成消耗20 AI点，必须用户确认
