## 火山引擎方舟 API 接入测试（晚上 19:30-20:45）

### 经过
用户提供了 IAM AccessKey (AKLT开头) + SecretKey (base64编码)，希望直接调方舟 API 获得更好的角色一致性。
- 安装了 `volcengine-python-sdk`（版本 5.0.25）
- SDK 路径在 `repo/lib/python3.12/site-packages`
- 修复了 `httpx` + `pydantic` 版本冲突（pydantic 2.x → 1.10.26, httpx 0.28→0.27）
- SDK 修复后 `Ark(api_key=...)` 可以初始化
- 但 `images.generate` 不支持 V4 签名（`ak & sk authentication is not supported for this method, please use api key instead`）
- SK base64 解码后为 `OTQxY2ZhODdkYWFhNDY0ZGI3YWY0OGI5ZWZjZGVjZjk`

### 关键发现
- 用户发送的 **IAM Access Key 管理页面** 明确提示："如果您需通过方舟进行大模型接入，建议使用 **方舟大模型专用 API Key**"
- 用户后续发送的 **API Key 管理页面** 是方舟的专用 API Key 入口，但 Key 被遮挡
- 用户提供的 AK/SK 是 IAM 级别的访问密钥，不是方舟大模型的 API Key
- 最终决定**不使用方舟 API**，继续走小艺通道

### 关键规则（自进化评估候选）
- 方舟 images.generate 只接受 API Key，不接受 AK/SK V4 签名
- SDK `volcenginesdkarkruntime` Ark 客户端接受 `api_key` 参数；`ak`+`sk` 参数仅部分资源支持
- pydantic 2.x + httpx 0.28 与 volcenginesdkarkruntime 不兼容，需降级
