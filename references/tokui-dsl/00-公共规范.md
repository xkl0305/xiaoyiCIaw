# TokUI DSL 公共规范

## **铁律**
> 1. 禁止编造任何组件类型名、属性名、属性值。只能使用本手册中穷举列出的字典。违反即渲染失败。**
> 2. 最终生成的 TokUI DSL 脚本必须使用 ```tokui``` 包裹起来，如下：
```tokui
xxx
xxx
```
---

## ⛔ 0. 绝对禁止事项（生成前必读）

1. **禁止发明组件类型**：组件名必须在组件分册中穷举列出。`barcode-box`、`price-card`、`data-grid` 等臆造名**一律不存在**。
2. **禁止发明属性名**：每个组件的合法属性在分册中逐一列出。写未列出的属性名无效（静默丢弃或渲染异常）。**必须使用属性简写**（如 `l:` 而非 `label:`、`tx:` 而非 `text:`），全称仅供理解含义。
3. **禁止发明变体值**：`v:` 后的变体名须经 §4 白名单校验，未知变体**静默丢弃**。
4. **禁止发明布尔属性**：只有 §3 列出的 key 才能裸写生效。
5. **禁止编造图表类型**：`chart` 的 `t:` 只允许《08-图表组件》列出的 20 种。
6. **禁止编造内置图标名**：`icon:` 只允许 §7 列出的 24 个。
7. **禁止编造颜色语义名**：仅 `primary/success/warning/danger/info/dark/light`。
8. **不确定就不写**：宁可少写属性也不要猜测。如果手册未提及某功能，说明该功能不存在。

## 1. 语法基础

### 1.1 标签格式

```
[type key:value key:value ... content]          ;; 自闭合
[type key:value]...[/type]                       ;; 容器（必须闭合）
```

- 第一个 token 是组件类型名
- 后续 `key:value` 为属性（key 为英文标识符）
- 最后剩余文本为裸内容（body text）
- 值含**空格**必须双引号：`ph:"请输入姓名"`
- 值含**逗号/竖线/分号**必须双引号：`d:"10,20,30"`

### 1.2 十条铁律

| # | 规则 | 错误示例 | 正确示例 |
|---|------|---------|---------|
| 1 | 属性间必须空格分隔（含 CJK 后） | `[item l:服务费（10%）tx:¥48]` | `[item l:服务费（10%） tx:¥48]` |
| 2 | `tr` 单元格之间用英文逗号分割，如果单元格的值含逗号，则用双引号包裹 | `2列：[tr 张三,25,北京,10,000]` | `[tr "张三,25,北京","10,000"]` |
| 3 | 变体必须带 `v:` 前缀，多变体逗号合并 | `[p muted 文本]` | `[p v:muted 文本]` 或 `[p v:"center,muted" 文本]` |
| 4 | `card` 有子元素时禁用 `tx`（`tx` = 自闭合叶子卡） | `[card tt:标题 tx:内容]...[/card]` | `[card tt:标题]...[/card]` |
| 5 | `p` 双模：有正文=自闭合，无正文=容器 | — | `[p 文本]` 或 `[p][btn tx:点击][/p]` |
| 6 | 正文里别写 `英文:值`（会被当属性） | `Q:什么是AI` | `Q：什么是AI`（全角冒号） |
| 7 | 正文含字面 `[` `]` 整段双引号包 | `[item arr[0]]` | `[item "arr[0]"]` |
| 8 | `chart` 属性顺序：`t 类型 → 样式/布局 → l 标签 → 数据` | `[chart d:"..." t:bar]` | `[chart t:bar ... d:"..."]` |
| 9 | 组件名必须在本手册清单内 | `[price-card ...]` | 不存在，用 `[card]` |
| 10 | 文本块（`p`/`h1~h6`/`item`）用裸内容，`tx:` 是自闭合展示组件专用 | `[p tx:文本]` | `[p 文本]` |

### 1.3 值类型

| 类型 | 格式 | 示例 |
|------|------|------|
| 颜色 | 语义名（`primary/success/warning/danger/info/dark/light`）或 6位hex**不带#**（`FF0000`） | `bg:primary` `bg:FF0000` |
| 数值 | 纯数字 | `w:480` `span:6` `v:72` |
| 布尔 | 只写 key | `stripe` `req` `dis` |
| 多选 | 逗号/竖线分隔，双引号包 | `d:"10,20|30,40"` |

### 1.4 别名映射

| 别名 | 实际类型 | 说明 |
|------|---------|------|
| `ol` | `list` | 自动带 `t:ol` |
| `ul` | `list` | 自动带 `t:ul` |
| `i` | `item` | 简写 |
| `case` | `test-case` | 简写 |
| `feature` | `welcome-feature` | 自闭合简写 |

## 2. 通用属性字典

以下属性可出现在多数组件上。**DSL 中必须使用「简写」列的名称**，「全称」列仅供理解含义，写全称无效（如写 `label:` 必须写 `l:`，写 `text:` 必须写 `tx:`）：

| 简写 | 全称 | 说明 |
|------|------|------|
| `id` | element id | 用于 `upd` 动态更新、`print:ID`、`openDialog` 目标 |
| `tt` | title | 标题（卡片/弹窗/步骤/提示等） |
| `tx` | text | 文本内容（**自闭合展示组件专用**：btn/tag/callout/stat/badge/dot 等） |
| `l` | label | 表单标签 / desc 项标签 / gauge 指标名 |
| `ph` | placeholder | 占位提示 |
| `u` | url | 链接地址 |
| `s` | src/source/size | 图片/视频/音频源；或尺寸（视组件） |
| `n` | name | 表单字段名 |
| `v` | value/variant | 值或变体（视组件） |
| `val` | value | 仅 `input`/`pwd` 存初始值（它们的 `v` 是变体） |
| `t` | type | 子类型（如 tag 颜色、图表类型、按钮变体） |
| `act` | action | 表单提交地址 / `upd` 动作（`open`/`close`/`toggle`） |
| `mtd` | method | 表单提交方法 |
| `clk` | onclick | 点击处理器名 |
| `sub` | onsubmit | 提交处理器名 |
| `dis` | disabled | 禁用（布尔） |
| `ro` | readonly | 只读（布尔） |
| `req` | required | 必填（布尔） |
| `chk` | checked | 选中（布尔） |
| `multi` | multiple | 多选（布尔） |
| `opt` | options | 选项简写串（radio/checkbox/select，**必须双引号**） |
| `w` `h` | width/height | 宽/高 |
| `bg` `fc` | background/font-color | 背景色/文字色 |
| `c` | color/colors | 颜色/系列颜色（`#` 开头，多色逗号分隔） |
| `target` | target | `a` 打开方式（默认 `_blank`） |
| `alt` | alt | `img` 替代文本 |
| `pos` | position | 方位（`top/bottom/left/right`） |
| `icon` | icon | SVG 图标名（§7 内置 24 个） |
| `i` | emoji/char icon | emoji 或字符图标 |
| `form` | form id | btn 显式绑定表单 |
| `reset` | reset action | btn 内置重置动作 |
| `print` | print action | btn 内置打印动作 |
| `data-*` | custom data | 透传为 HTML `data-*` 属性 |

## 5. 容器与自闭合规则

### 5.1 容器组件完整清单（必须写 `[/type]` 闭合）

组件字典中标注为「容器」的类型必须写 `[/type]` 闭合（完整清单见附录第 1 条）。

### 5.2 自闭合逃逸（在容器清单内但特定条件自动当自闭合）

| 条件 | 组件 |
|------|------|
| 有 `tx` 属性的容器 → 自闭合 | `callout` 等（`[callout t:info tx:说明]`） |
| **例外**：`tx` 不当 body | `tn` / `popover` / `input-tag` / `watermark` / `badge-box` |
| `tn` 带 `leaf` → 自闭合叶子 | `tn` |
| `input-tag` 带 `tags` → 自闭合 | `input-tag` |
| `radio`/`select`/`checkbox` 带 `opt:"..."` → 自闭合 | `radio` `select` `checkbox` |
| `checkbox` 单布尔（无 `opt` 无 `multi`）→ 自闭合 | `checkbox` |
| `thead` 带 `cols` → 自闭合 | `thead` |
| `chart` 带数据属性 → 自闭合 | `chart`（`d`/`tasks`/`rows`/`nodes+flows`/gauge·progress的`v`） |

### 5.3 原始内容模式（容器内 `[` 视为字面文本）

`code` `md` `diff` `terminal` `sandbox` `artifact-code`

## 8. 动态更新 `[upd]`

`[upd id:组件ID 属性:新值...]` — 查找已渲染的组件并按 ID 更新其属性。

> `[upd id:组件ID 属性:新值...]` — 查找已渲染的组件并按 ID 更新其属性。

### 各组件支持的 upd 更新键

| 组件 | 支持的更新键 | 示例 |
|------|-------------|------|
| `progress` | `v`（进度值）、`status` | `[upd id:p1 v:75]` |
| `switch` | `checked` | `[upd id:sw1 checked]` |
| `slider` | `v` | `[upd id:sl1 v:80]` |
| `rate` | `v` | `[upd id:r1 v:4]` |
| `numinput` | `v` | `[upd id:n1 v:100]` |
| `input` | `v`（值）、`dis`、`ro` | `[upd id:inp1 v:新值]` |
| `chat-input` | `dis` | `[upd id:ci1 dis]` |
| `notification` | `title`、`text` | `[upd id:nf1 title:新标题]` |
| `chart` | `d`（数据）、`l`（标签） | `[upd id:c1 d:"10,20,30"]` |
| `card` | `title` | `[upd id:cd1 title:新标题]` |
| `step` | `status` | `[upd id:st1 status:done]` |
| `think` | `status` | `[upd id:th1 status:done]` |

## ⛔ 附录：AI 生成 DSL 前必做检查清单

**每次生成 TokUI DSL 脚本前，必须逐项核对以下 10 条：**

1. ☐ **组件类型**：每个 `[type]` 的 type 值必须在以下穷举列表中：
   - 文本基础：`h1`~`h6` `p` `a` `img` `hr` `dv` `md` `code` `tag` `b` `strong` `em` `mark` `del` `sub` `sup`
   - 状态反馈：`callout` `spin` `skeleton` `shimmer` `empty` `result` `barcode` `qrcode` `dot` `badge` `badge-box` `toast` `notification` `progress` `stat` `countdown` `thumb` `toggle` `toggle-group` `copy` `upd` `tooltip` `popover` `popconfirm` `hover-card` `hover-trigger` `hover-content` `input-tag` `dropdown` `dd-item` `backtop` `pagination` `breadcrumb` `calendar` `watermark` `avatar` `file` `chat-input` `msg-actions`
   - 思考计划：`think` `think-chain` `think-step` `plan` `plan-step` `agent`
   - AI 对话：`bubble` `toolbar` `tool-call` `typing` `quick-reply` `suggestions` `suggestion` `source` `diff` `file-tree` `ft-folder` `ft-file` `terminal` `sandbox` `test-result` `test-case` `case` `commit` `quote` `latency` `video` `audio` `conversations` `conv` `welcome` `welcome-feature` `feature` `attachments` `attach` `artifact` `artifact-code` `artifact-preview` `command` `command-group` `command-item` `canvas` `canvas-content`
   - 布局容器：`card` `ft` `row` `col` `list` `item` `tabs` `tab` `accordion` `collapse` `dialog` `drawer` `imgs` `timeline` `ti` `steps` `step` `desc` `desc-item` `carousel` `carousel-item` `tree` `tn` `menu` `menu-item` `resizable` `scroll-area` `sidebar` `sidebar-content` `sidebar-footer` `print-area`
   - 表单：`form` `input` `pwd` `textarea` `select` `radio` `opt` `checkbox` `switch` `slider` `rate` `numinput` `btn` `btngroup` `picker` `cascader` `transfer` `upload` `datepicker` `timepicker` `datetimepicker`
   - 表格：`table` `thead` `tbody` `tr` `tcol`
   - 图表：`chart`（`t:` 见下方第 5 条）
2. ☐ **组件属性**：每个属性名是否在该组件的属性表中列出？
3. ☐ **变体值**：`v:` 的值是否在 §4 变体白名单中？
4. ☐ **图标名**：`icon:` 的值是否是 §7 的 24 个内置图标之一？
5. ☐ **图表类型**：chart 的 `t:` 值必须是以下 20 种之一：`line` `bar` `pie` `donut` `area` `radar` `scatter` `bubble` `doughnut` `gauge` `progress` `funnel` `treemap` `heatmap` `candlestick` `box` `sankey` `gantt` `mix` `matrix`
6. ☐ **容器闭合**：容器组件是否有对应的 `[/type]`（或符合自闭合逃逸规则）？
7. ☐ **布尔属性**：布尔属性是否只写了属性名、没有 `:值`？
8. ☐ **颜色值**：颜色是否使用语义名或 6 位 hex（不带 #）？
9. ☐ **嵌套规则**：是否违反容器嵌套约束（如 p 只能包含内联元素）？
10. ☐ **opt 简写**：`opt:"..."` 是否用双引号包裹、项用 `;` 分隔、项内 `value:label`？

**如果任何一项不在手册字典中，立即停止——你正在编造不存在的组件或属性！**
